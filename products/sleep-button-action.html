Sleep button action vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the power button page, not the lid close page, and not sleep vs forever. Power is the chassis/dock power key. Lid is the hinge. Timeouts are idle. This page is the remaining Sleep key: Power Options → Power buttons and lid → Sleep button action. That is SBUTTONACTION. Balanced AC is often Sleep. Fn+moon, a keyboard crescent, or a dock Sleep pad is Standby. Interactive-only LEXXII-Materialize-Forever misses the hour. Task Scheduler still shows Ready.

The problem

The lid-close pack already tells you plugged-in lid action is Do nothing. The power-button pack already tells you the chassis power key on AC is Do nothing. Sleep after can already be Never. That work can be done and one moon key still kills the loop. Balanced Sleep button action on AC is Sleep. A closed-lid Ultra 7 on a cooling stand still has Fn+F-row, an external keyboard Sleep, or a dock pad that Windows maps to the same ACPI Sleep button. The operator meant display-off. Windows Sleeps. grok.exe pauses. The named task still prints Ready and last result 267009 (still-running). The operator thinks power-button lied. A different key did the Sleep.

This is not power-button. Power is PBUTTONACTION. This is not lid. Lid is LIDACTION. This is SBUTTONACTION. Do not set Shut down as a “fix.” Do not Hibernate the forever desk from a Fn combo. Do not treat Start-menu Sleep as this row — that is a software Sleep request, not the Sleep button. Do nothing on AC is the pass. On battery may stay Sleep if this laptop actually travels. Do not install systemd to paper over a moon key. Do not mint a Vercel slug because a Fn press looked like a dead task.

What to change (plugged-in Grok desk)

  1. Confirm lid-close on AC is already Do nothing — if closing the lid still Sleeps, that is lid-close, not this page.
  2. Confirm sleep timeouts are already honest — plugged-in sleep / hibernate are not 5–20 minutes. See sleep-vs-forever.
  3. Confirm power-button on AC is already Do nothing — if the chassis power key still Sleeps, that is power-button, not this click.
  4. Power Options → Change plan settings → Change advanced power settings → Power buttons and lid → Sleep button action — set Plugged in to Do nothing. Same row exists under Control Panel → Choose what the power buttons do → When I press the sleep button. On battery may stay Sleep if this laptop actually travels.
  5. Leave Power button action and lid action as siblings — this click is SBUTTONACTION only. Do not “fix” the moon key by rewriting PBUTTONACTION or LIDACTION.
  6. Leave the Balanced (or current) plan in place — this page is one button knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  7. Confirm, then soak — query the buttons subgroup. Do nothing on AC is the pass. Do not paste live brokerage numbers. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_BUTTONS
powercfg /a

SUB_BUTTONS is Power buttons and lid. SBUTTONACTION is Sleep button action. Typical values: 0 = Do nothing, 1 = Sleep, 2 = Hibernate, 3 = Shut down. Some images also list 4 = Turn off the display — that is still not this page’s pass. 0 on AC is the pass for this desk. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as Do nothing. If powercfg also omits the alias, this firmware did not expose the knob — stop; do not invent a registry hack on a public page. Power button action is a sibling, not this click. Lid action is a sibling, not this click. Start-menu Sleep is not this click.

How it splits from the other playbooks

  • Power button action — chassis/dock power key (PBUTTONACTION). This page is the moon / Sleep key (SBUTTONACTION).
  • Lid close Do nothing — hinge action (LIDACTION). Not a key.
  • Sleep vs forever — idle timeouts and Modern Standby. Not a button.
  • Sleep after — minutes knob (STANDBYIDLE). No key press.
  • Allow hybrid sleep — whether Sleep writes a hiberfile. Not which key starts Sleep.
  • This page — AC Sleep button action = Do nothing so Fn+moon, a keyboard Sleep, or a dock Sleep pad cannot Sleep an Interactive Grok CLI while the named task still looks Ready.

Soak test (what "passes" means)

  1. Lid already Do nothing on AC. Power button already Do nothing on AC. Sleep timeouts already honest. Otherwise this soak is lying about which key fired.
  2. Press the Sleep key once (Fn+moon, keyboard crescent, or dock Sleep pad), lid closed, dedicated NIC plugged. The session stays awake. The Grok TUI still accepts input. Sleep or a black panel is a fail.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 after a Sleep-key Sleep is not forever.
  4. AC index still 0. If someone set Sleep “so the moon key still works,” restore Do nothing. Use Start-menu Shut down when you mean off — after Fast Startup is honest. Start-menu Sleep is a different path; this soak does not claim to disable it.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof the Sleep key is already Do nothing.

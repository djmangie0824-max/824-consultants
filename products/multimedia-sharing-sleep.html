When sharing media vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page and not the powercfg /requests diagnostic. Sleep-vs-forever sets timeouts. Requests tells you who is holding DISPLAY / SYSTEM / AWAYMODE right now. This page is the Power Options policy that can create those holders with no player on screen: Multimedia settings → When sharing media.

Download markdown Sleep vs forever first Read the holders

The problem

Balanced and some OEM “entertainment” plans ship When sharing media as Prevent the computer from sleeping or Allow the computer to enter Away Mode. Windows Media Player sharing, nearby sharing leftovers, Cast / DLNA, and a few vendor “Smart Share” helpers leave that row on Prevent even when you are not playing anything. The sleep timeout then looks like a lie. Task Scheduler still shows Ready. LEXXII-Materialize-Forever last-run is stale because the session never idled.

Three values, one forever-desk answer. Allow the computer to sleep is the plugged-in Grok desk. Prevent the computer from sleeping is a silent SYSTEM pin for as long as Windows thinks media is shared. Allow the computer to enter Away Mode is fake-sleep: fans, NIC, and session stay up while the panel pretends to be off. Away Mode is not host-forever. It is a media-center leftover. Do not cargo-cult it onto a closed-lid cooling-stand laptop.

The sibling row When playing video is display quality versus power, not a share policy. Optimize video quality can keep the panel awake while a video is actually playing. That is expected. It is not permission to leave When sharing media on Prevent. Read /requests after the click: AWAYMODE and SYSTEM should print None when nothing is sharing.

Do not set When sharing media to Prevent to “keep the forever loop alive.” That pins sleep; it does not run the hourly. Do not use Away Mode as a substitute for lid-close Do nothing. Do not change this on battery to paper over an unplugged desk.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever.
  2. Power Options → Change plan settings → Change advanced power settings → Multimedia settings → When sharing media — Plugged in = Allow the computer to sleep. Not Prevent. Not Away Mode. Battery can stay Prevent; this desk is AC + UPS.
  3. When playing video — leave as a quality choice. Do not treat Optimize video quality as a SYSTEM pin. If a video is not playing, this row should not hold anything.
  4. If the Multimedia settings subgroup is missing — unhide it, then set it. Do not invent a random registry value on a public page.
  5. Confirm with requests — idle session, no share, no player. DISPLAY and SYSTEM print None. Then soak. Do not paste live brokerage numbers next to that output.
powercfg /q SCHEME_CURRENT SUB_MULTIMEDIA
powercfg /requests

SUB_MULTIMEDIA is the subgroup on current plans that expose it. If query prints nothing, the GUI path above still applies — some SKUs hide the alias. Empty /requests after Allow, with nothing sharing, is the pass. A leftover AWAYMODE holder with Allow already set is a vendor helper, not this row — go back to requests and name the PROCESS/SERVICE.

How it splits from the other playbooks

  • Sleep vs forever — timeouts, Modern Standby, Interactive-only, result 267009.
  • powercfg /requests — who is holding DISPLAY / SYSTEM / AWAYMODE right now.
  • Allow wake timers — RTC if sleep still happened.
  • Lid close Do nothing — the lid is not a Sleep key. Away Mode is not a lid policy.
  • This page — When sharing media = Allow the computer to sleep on AC so a share policy does not pin the session.

Soak test (what "passes" means)

  1. Sleep timeouts already honest on AC. Otherwise this soak is lying.
  2. When sharing media on the plugged-in plan is Allow the computer to sleep, not Prevent, not Away Mode.
  3. Idle session, no player, no Cast. powercfg /requests prints None under SYSTEM and AWAYMODE.
  4. Starting a real share (if you even have one) may hold SYSTEM; stopping the share clears it. A holder that survives “stop sharing” is a vendor helper, not this row.
  5. No fourth Grok TUI. Last result 267009 is still-running, not a share policy.

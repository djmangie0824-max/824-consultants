Energy Efficient Ethernet vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB selective suspend page, not the PCI Express ASPM page, and not the USB Ethernet buy guide. USB suspend sleeps a hub. ASPM parks a PCIe tunnel. Ethernet is the NIC SKU. This page is IEEE 802.3az Low Power Idle — Green Ethernet / EEE on the adapter itself — which can gap or downshift the dedicated NIC while Task Scheduler still shows Ready.

Download markdown USB selective suspend first PCIe link state

The problem

The USB selective suspend pack already tells you to disable USB suspend on AC and uncheck “turn off this device” on the USB Root Hub that feeds Ethernet. That is still the first click. If the dedicated NIC stays Present in Device Manager but ping still gaps after thirty idle minutes, or the link light stays on while the negotiated speed falls to 100 Mb, the next knob is on the adapter: Energy Efficient Ethernet / Green Ethernet / EEE.

IEEE 802.3az lets the PHY enter Low Power Idle when the wire is quiet. Realtek often labels it Green Ethernet. Intel often labels it Energy Efficient Ethernet, sometimes next to Ultra Low Power. A Grok desk that ships through GitHub MCP or a named hourly task does not want a sleepy PHY. LEXXII-Materialize-Forever can still claim Ready while the NIC is in LPI. The operator thinks Git hung. The PHY napped.

This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd to paper over Green Ethernet. Do not mint a Vercel slug because ping dropped once.

What to change (plugged-in Grok desk)

  1. Confirm the USB layer is already done — Power Options → USB settings → USB selective suspend → Plugged in = Disabled. USB Root Hub that feeds Ethernet already has “Allow the computer to turn off this device to save power” unchecked. See that playbook. If that is still Enabled, stop here.
  2. Device Manager → Network adapters → the dedicated Ethernet adapter — not Wi-Fi, not Bluetooth, not a Hyper-V switch. Properties → Advanced.
  3. Set Energy Efficient Ethernet / Green Ethernet / EEE to Disabled — vendors rename it. Disable the property that is present. If Ultra Low Power or Reduce Speed During Standby is listed on the same adapter, Disabled. Leave Speed & Duplex on Auto unless a soak already proved a fixed 1 Gb is required.
  4. Same adapter → Power Management — uncheck Allow the computer to turn off this device to save power. That checkbox on the NIC is not the USB Root Hub checkbox from the USB pack. Two different objects. Do not hunt every adapter on the machine.
  5. Confirm, then soak — query the adapter. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
Get-NetAdapter | Where-Object Status -eq 'Up' | Format-Table Name, InterfaceDescription, LinkSpeed
Get-NetAdapterAdvancedProperty -Name '*' | Where-Object { $_.DisplayName -match 'Energy|Green|EEE|Idle' } | Format-Table Name, DisplayName, DisplayValue

If no Energy / Green / EEE property exists on the dedicated NIC, this driver did not expose the knob — stop; do not invent a registry hack on a public page. The Power Management checkbox may still apply.

Soak test (what "passes" means)

  1. USB selective suspend already Disabled on AC. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. Ping out that NIC. One silent gap is a fail on this page — but if the NIC vanished from Device Manager, it is the USB or ASPM page, not this one.
  3. Link speed after idle matches link speed before idle. A quiet downshift to 100 Mb is a fail here.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a napping PHY is not forever.

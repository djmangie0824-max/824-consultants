schtasks last result 267009 vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Windows Task Scheduler forever pack that creates LEXXII-Materialize-Forever. It is not the Grok 7-day expiry pack. It is not the isolation-empty skip recreate pack. Those pages arm, disclose, or refuse to mint. This page is the remaining decoder: Last Result 267009. Decimal 267009 is HRESULT 0x41301, SCHED_S_TASK_RUNNING. It is a success-class scheduler status, not a Win32 error. Operators treat the column as exit 1. They spawn another grok.exe. They recreate Grok lanes. They write “the 5-minute pulse is dead.” Status is Running. Next run is still in the future. The previous instance has not returned. That is the pulse working.

The problem

Task Scheduler GUI and schtasks /Query /FO LIST /V print two different facts in two columns. Status is now: Ready, Running, Disabled, Could not start. Last Result is either the last action’s exit code or a scheduler HRESULT while the action is still in flight. On a 5-minute Interactive-only Grok desk, the named tasks overlap their own query. LEXXII-Materialize-Forever, Pages-Heal, Ship, Compound, and Wormhole sit at Status=Running and Last Result=267009 for the whole fire. That is Queue / ignore-new doing its job. It is not proof the prompt died.

267009 looks like a four-digit fail because every other Windows error the operator knows is decimal. It is not ERROR_FILE_NOT_FOUND. It is not Git exit 128. Convert: 0x41301 = 267009. The 0x000413xx band is Task Scheduler success status, not Win32. Last Result 0 means the last completed run returned success. Last Result 1 means the last completed action returned 1 — that is the real fail this pack does not paper over. Last Result 267011 (SCHED_S_TASK_HAS_NOT_RUN) with last-run 1999-11-30 is the never-fired daily that windows-task-forever already healed. Do not mix those three.

Extra Grok TUI windows split the same quota. Four grok.exe already running is already too many for “one more to be sure.” Fusion is 32 queued subagents plus the 5-minute Windows tasks. Do not install systemd because 267009 printed. Do not paste live brokerage numbers next to a Last Result dump. Capital stays off Pages.

What to run (plugged-in Grok desk)

  1. Confirm the named task exists — if Query says the task does not exist, this decoder has nothing to decode. Create it with windows-task-forever. Do not mint a Grok lane as a substitute.
  2. Query, do not start — schtasks /Query /TN "\LEXXII-Wormhole" /FO LIST /V (or Materialize / Pages-Heal / Ship / Compound). Read Status, Last Result, Last Run Time, Next Run Time, Repeat: Every as four facts. Do not /Run because 267009 scared you.
  3. Classify Last Result — 267009 while Status=Running: still in flight. 0 while Status=Ready: last completed success. 1 while Status=Ready: last action failed. 267011: never run. Convert unknown decimals with a hex calculator to the 0x413xx band before calling them fails.
  4. Count grok.exe, then stop — extra windows split quota. If Status is Running, the fire already has a process. Do not open a fifth TUI. Do not install systemd. Do not git push from this host to “heal” a Last Result.

:: 267009 = 0x41301 SCHED_S_TASK_RUNNING

:: 267011 = 0x41303 SCHED_S_TASK_HAS_NOT_RUN
:: 0 = last completed action succeeded
:: 1 = last completed action returned 1

HRESULT 0x41301 is documented as “The task is currently running.” The GUI decimal is 267009. 0x41300 is Ready (267008). 0x41303 is has-not-run (267011). Those three are scheduler status, not cmd exit codes. Exit 0 and exit 1 live in the same Last Result column after the action returns. Read Status first. Then read Last Result. Then read Next Run. A 5-minute Repeat with Next Run a few minutes out is the pulse. A Ready + 1 + next-run in the past is a fail of the action, logged in the lane .log, not healed by another TUI.

How it splits from the other playbooks

  • Windows Task Scheduler forever — create / heal the named task (hourly-then-5m, batteries, Queue). This page assumes the task exists and decodes Last Result.
  • Grok scheduler 7d — in-session durable lanes expire in 7 days. Host-forever is still the Windows task. This page does not recreate those IDs.
  • Isolation skip — empty scheduler_list in a headless isolation is skip recreate, keep forever IDs. 267009 is not emptiness.
  • Sleep vs forever — idle timeouts and Interactive-only. 267009 can print while the session is awake. It is not proof S0ix ate the pulse.
  • This page — Status + Last Result + Next Run. 267009 = still-running. Do not spawn another grok.exe.

Soak test (what "passes" means)

  1. Named task exists. Repeat is 5 minutes (heal/ship/compound/wormhole) or 15 minutes (UMI/BI). Batteries allowed. Duration 1 day.
  2. During a fire: Status=Running and Last Result=267009. Next Run still in the future. That is a pass. Do not /Run. Do not open another TUI.
  3. After a fire returns 0: Status=Ready and Last Result=0. Last Run Time moved. That is also a pass.
  4. Last Result=1 is a fail of the action, not of this decoder. Read the log. Do not relabel it 267009.
  5. Last Result=267011 with last-run 1999-11-30 is a fail of the trigger pack, not this decoder.
  6. No extra Grok TUI. Isolation-empty still skip recreate. Forever IDs kept. Not systemd. Not /home/workdir. Capital stays off Pages.

Processor core parking vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Minimum processor state page, not the powercfg /requests page, and not a High performance plan essay. Min-state sets the frequency floor. This page is the remaining core count: Power Options → Processor power management → Processor performance core parking min cores. That is CPMINCORES. Balanced AC can leave that row at 10% or 0%. Windows parks cores. An Interactive Grok CLI on an Ultra 7 looks hung. Task Scheduler still shows Ready.

The problem

The processor min-state pack already tells you PROCTHROTTLEMIN on AC is 100%. Frequency floor can be honest and the TUI still starves. Core parking is a different row in the same subgroup. Windows may park most logical processors so a 12-core Ultra 7 is running on a sliver. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. Cores were parked.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. Min-state can still be 100. The parking policy is the liar. Do not install systemd to paper over parked cores. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide three other forever-loop bugs.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here.
  2. Confirm Minimum processor state is already 100% on AC — if that row is still 5%, that is processor min-state, not this page.
  3. Power Options → Change plan settings → Change advanced power settings → Processor power management → Processor performance core parking min cores — set Plugged in to 100%. On battery may stay lower if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave Processor performance core parking max cores at 100% on AC — this page does not cap the ceiling. Do not drop Maximum cores to save a watt.
  5. Leave the Balanced (or current) plan in place — this page is one processor knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak — query the processor subgroup. 100 on AC for CPMINCORES is the pass. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_PROCESSOR
powercfg /a

SUB_PROCESSOR is the processor subgroup. CPMINCORES is Processor performance core parking min cores. 100 on AC is the pass for this desk: Windows may not park below 100% of cores. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as 100. If powercfg also omits the alias, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. Heterogeneous thread scheduling is a sibling, not this click. System cooling policy is a sibling, not this click. Intel Speed Shift / EPP is a sibling, not this click.

How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). This page is unparked-core floor (CPMINCORES).
  • Sleep vs forever — Modern Standby, Interactive-only logon, result 267009 still-running as a sleep tell. This page is the awake core count.
  • powercfg /requests — DISPLAY / SYSTEM / AWAYMODE holders. A named process, not a parked-core percent.
  • System cooling policy — Passive vs Active fans. Thermal throttle, not parking. Not this click.
  • Heterogeneous thread scheduling / Intel Speed Shift — sibling processor rows. Not this click. Do not invent a registry paste on this page.
  • This page — AC core parking min cores so Balanced cannot park an Ultra 7 down to a sliver while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Minimum processor state already 100% on AC. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input. Task Manager Performance does not show most cores Parked while grok.exe is the foreground session.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with cores parked is not forever.
  4. Core parking max cores still 100% on AC. If someone dropped the ceiling, restore it. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof cores are already unparked.

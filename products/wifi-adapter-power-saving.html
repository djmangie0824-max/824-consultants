Wireless adapter power saving vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB 3 Link Power Management page, not the Energy Efficient Ethernet page, and not the USB Ethernet buy guide. SuperSpeed U1/U2 is a USB NIC. EEE is the Ethernet PHY. Ethernet is still the primary rail. This page is the remaining radio: Power Options → Wireless Adapter Settings → Power Saving Mode. Maximum Power Saving can drop Wi-Fi after idle so the fallback is gone the moment the dedicated NIC flaps. Task Scheduler still shows Ready.

Download markdown USB 3 LPM first USB Ethernet stays primary

The problem

The USB selective suspend and USB 3 LPM packs already tell you to keep the dedicated NIC awake on AC. That work can be done and a ship still dies when the NIC re-enumerates, because the radio that should catch the gap is napping. Balanced defaults Wireless Adapter Settings to Medium or Maximum Power Saving on AC. The adapter parks MIMO antennas, misses beacons, and looks disconnected for seconds. GitHub MCP vanishes. A git push hangs. LEXXII-Materialize-Forever still claims Ready. The operator thinks Git is missing. The radio left.

This happens while the machine is awake. It is not Modern Standby. It is not USB U1/U2. It is not IEEE 802.3az. Do not install systemd to paper over a napping radio. Do not mint a Vercel slug because Wi-Fi blinked. Do not make Wi-Fi the primary rail — buy the NIC.

What to change (plugged-in Grok desk)

  1. Confirm the USB layer is already done — USB selective suspend Plugged in = Disabled. USB 3 Link Power Management on AC = Off if the row exists. Dedicated NIC still exists. See USB suspend and USB 3 LPM. If those are still wrong, stop here.
  2. Power Options → Change plan settings → Change advanced power settings → Wireless Adapter Settings → Power Saving Mode — set Plugged in to Maximum Performance. On battery may stay Medium Power Saving if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  3. Device Manager → Network adapters → the Wi-Fi adapter → Properties → Power Management — uncheck Allow the computer to turn off this device to save power. That checkbox is the radio sibling of the USB hub checkbox. Do it here, not as a second USB essay.
  4. Leave the Balanced (or current) plan in place — this page is one wireless knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  5. Confirm, then soak — query the wireless subgroup. Maximum Performance on AC is the pass. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_WIFI
powercfg /devicequery wake_armed

SUB_WIFI is the wireless subgroup on SKUs that expose it. Maximum Performance on AC is the pass for this desk. If the subgroup is missing, this firmware or edition did not expose the plan row — stop at the Device Manager checkbox; do not invent a registry hack on a public page. Hidden is not the same as Maximum Performance.

How it splits from the other playbooks

  • USB selective suspend — device-level D3 / U3 and the hub Power Management checkbox. USB, not radio.
  • USB 3 Link Power Management — SuperSpeed U1/U2 on the dedicated NIC. Not Wi-Fi.
  • Energy Efficient Ethernet — IEEE 802.3az / Green Ethernet on the adapter PHY. The NIC stays Present.
  • Network connectivity in Standby — NIC policy during S0ix, after the laptop actually slept.
  • USB Ethernet review — hardware criteria, SKU pending. Ethernet stays the primary rail.
  • This page — radio Power Saving Mode so Wi-Fi is still there when SuperSpeed blinks. Not a Wi-Fi-only desk.

Soak test (what "passes" means)

  1. USB suspend already Disabled on AC. USB 3 LPM already Off on AC if the row exists. Lid close already Do nothing on AC. Dedicated NIC still Present. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, Ethernet plugged. The Wi-Fi adapter stays Present in Device Manager. One silent radio reassociate is a fail on this page.
  3. Do not unplug Ethernet as a required soak. The primary rail stays the dedicated NIC. If you need a fallback proof, disable the Ethernet adapter for 60 seconds — not the cable yank — and confirm Wi-Fi already has a known SSID and does not sit in Power Saving. Then re-enable Ethernet.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a napping radio is not forever.
  5. No fourth Grok TUI. Last result 267009 is still-running, not a Wi-Fi bug.

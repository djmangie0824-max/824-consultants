PCI Express Link State Power Management vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB selective suspend page, not the Modern Standby page, and not the USB Ethernet buy guide. USB suspend sleeps a hub. Sleep-vs-forever is S0ix. Ethernet is the NIC SKU. This page is ASPM: the PCI Express link-state policy that can park a Thunderbolt/USB4 dock or an NVMe while Task Scheduler still shows Ready.

Download markdown USB selective suspend first Sleep vs forever

The problem

The USB selective suspend pack already names this layer and tells you not to cargo-cult it. That warning is still true. Fix USB first. If the dedicated NIC still vanishes after USB suspend is Disabled on AC, the dock still blinks, or the NVMe used for local models drops after thirty idle minutes, the next knob is Power Options → PCI Express → Link State Power Management.

Balanced defaults that setting to Moderate or Maximum power savings. ASPM L1 lets the root port nap. A USB4/Thunderbolt dock is a PCIe tunnel, not a USB gadget. When the link parks, displays black, the dedicated NIC looks unplugged even though USB suspend is already off, and LEXXII-Materialize-Forever still claims Ready. GitHub ships hang. The operator thinks Git is missing. The PCIe link left.

This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd to paper over ASPM. Do not mint a Vercel slug because the dock blinked.

What to change (plugged-in Grok desk)

  1. Confirm the USB layer is already done — Power Options → USB settings → USB selective suspend → Plugged in = Disabled. See that playbook. If that is still Enabled, stop here.
  2. Power Options → Change plan settings → Change advanced power settings → PCI Express → Link State Power Management — set Plugged in to Off. On battery may stay Moderate power savings if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  3. Leave the Balanced (or current) plan in place — this page is one PCI Express knob, not a cargo-cult switch to “High performance” that hides three other forever-loop bugs. Do not rename the plan. Do not claim a fleet GPO.
  4. Confirm, then soak — query the active scheme. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_PCIEXPRESS
powercfg /a

SUB_PCIEXPRESS is the PCI Express subgroup. ASPM Off on AC reads as the Off / no-power-saving setting, not Moderate or Maximum. If the subgroup is missing, this firmware did not expose the knob — stop; do not invent a registry hack on a public page.

Soak test (what "passes" means)

  1. USB selective suspend already Disabled on AC. Lid close already Do nothing on AC. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dock + dedicated NIC plugged. Displays stay lit or immediately resume without a Device Manager hunt. One silent dock reset is a fail on this page.
  3. NVMe used for local models stays Present. A disk that vanishes and re-enumerates is a fail.
  4. Ping out the USB NIC. One silent gap is a fail — but if USB suspend is still Enabled, it is the USB page, not this one.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a parked PCIe dock is not forever.

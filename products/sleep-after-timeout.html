Sleep after vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the sleep vs forever diagnosis, not the System unattended sleep timeout page, and not Hibernate after idle. Sleep-vs-forever names Modern Standby, Interactive-only logon, and result 267009 as a read. Unattended-sleep is UNATTENDSLEEP — the hidden re-nap after a wake-timer. Hibernate after is HIBERNATEIDLE to ACPI S4. This page is the remaining attended minutes knob: Power Options → Sleep → Sleep after. That is STANDBYIDLE (GUID 29f6c1ee-7b59-4e01-8a3d-97d2b4a0a8e0). Balanced AC is often 10, 15, or 20 minutes. Interactive-only LEXXII-Materialize-Forever misses fires. Task Scheduler still shows Ready.

The problem

LEXXII-Materialize-Forever is Interactive-only. That is honest for a Grok TUI that must not stack a fourth window. Lid can already be Do nothing on AC. Sleep button can already be Do nothing. Power button can already be Do nothing. Hibernate can already be off, or Hibernate after can already be Never. Allow wake timers can already be Enable. That work can be done and a 5-minute pulse still dies. Balanced Sleep after on AC is still 10–20 minutes. Windows counts STANDBYIDLE in seconds. 600 is ten minutes. 1200 is twenty. The signed-in session goes to S3, or to S0ix on a Modern Standby SKU. Task Scheduler still prints Ready. Next-run sits in the future. Last result 267009 (still-running) is a frozen process, not a live pulse. No 5-minute fire happens until someone wakes the box and the Interactive session is actually there.

The diagnosis pack already told you sleep eats the loop. It did not give you this click. Sibling playbooks already link here as sleep-after-timeout.html and then 404 as the custom deny wall — missing from main, not a vault. This page is that landing. Host-forever is the Windows task on a 5-minute pulse. Grok in-session schedulers expire in 7 days even when durable. They are not this knob. Do not install systemd to paper over 15 minutes. Do not mint a Vercel slug because Sleep after fired. Do not paste live NLV next to a powercfg dump. NLV stays off Pages.

What to change (plugged-in Grok desk)

  1. Confirm the hardware Sleep keys are not this click — lid close on AC is Do nothing if this soak will close the lid (lid-close). Sleep button on AC is Do nothing if a Fn+moon or keyboard Sleep key exists (sleep-button). Power button on AC is Do nothing if a chassis press is in the well (power-button). If a key still Sleeps, this minutes row is not the liar yet.
  2. Power Options → Change plan settings → Change advanced power settings → Sleep → Sleep after — set Plugged in to Never (0 minutes). On battery may stay 10–20 minutes if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  3. Leave System unattended sleep timeout alone on this click — that is UNATTENDSLEEP. After this page is Never, the unattended pack is the next hidden row.
  4. Leave Hibernate after and /h off alone on this click — HIBERNATEIDLE is idle-to-S4. powercfg /h off deletes S4. Sleep after Never still loses the session if Hibernate after is 180 minutes.
  5. Leave Allow hybrid sleep and Allow wake timers alone on this click — hybrid sleep is a hiberfile then S3. Wake timers recover a logged-on session that slept. This page tries not to sleep on attended idle.
  6. Leave the Balanced (or current) plan in place — this page is one Sleep-after knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO. Do not install systemd on this Windows profile.
  7. Confirm, then soak — query STANDBYIDLE. AC index 0 is the pass. GUI Never = 0 seconds in powercfg. Do not paste live brokerage numbers. Do not paste auth.json.

SUB_SLEEP / STANDBYIDLE is Sleep after (GUID 29f6c1ee-7b59-4e01-8a3d-97d2b4a0a8e0). AC index is seconds. 0 is Never. 600 is 10 minutes. 1200 is 20. powercfg /change standby-timeout-ac speaks minutes. Apply with /setactive. Hidden is not Never. UNATTENDSLEEP is unattended re-sleep. HIBERNATEIDLE is Hibernate after. VIDEOIDLE is Turn off display after.

Soak test (what "passes" means)

  1. Lid already Do nothing on AC if this soak closes the lid. Sleep button and power button already Do nothing if those keys exist.
  2. Query STANDBYIDLE. Honest prove: set AC to 120 seconds via /setacvalueindex, idle three minutes, confirm sleep. Then set 0. Repeat — session stays signed in. Leave Never. Do not leave a two-minute prove value on a forever desk.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Last-run must advance across the soak.
  4. STANDBYIDLE still 0 on AC. Do not switch the whole plan to High performance. Do not /h off as a substitute.
  5. STANDBYIDLE already 0 with remaining S0ix freeze is windows-sleep-vs-forever, not a second paste of 0.
  6. No fourth Grok TUI. Last result 267009 is still-running. Grok schedulers expire in 7 days even when durable.

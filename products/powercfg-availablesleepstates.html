powercfg /a vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Sleep vs forever timeout page, not the CSEnabled registry page, not Hybrid Sleep, not Hibernate Off, not Fast Startup, and not sleepstudy or /lastwake. Those packs set a policy or read a history. This page is the remaining map: powercfg /a (/availablesleepstates). It names which ACPI / Modern Standby states the firmware will actually enter. A Hybrid Sleep click on a box that has no S3 is a ghost. A Sleep-after timer on S0ix is not S3. Read the map first.

The problem

Every sibling says “run powercfg /a.” Almost none of them are that dump. The operator sets Sleep after to Never, turns Hibernate off, or hunts Hybrid Sleep in the GUI, then wonders why the row is missing or why lid-close still looks like a black screen with the NIC up. Task Scheduler still prints Ready and last result 267009 (still-running). The Grok TUI is still a process. The firmware never had S3. Or it had S3 and someone is treating S0ix lines as a BIOS bug.

/a is availability, not policy. It does not change STANDBYIDLE. It does not flip CSEnabled. It does not write hiberfil.sys. It prints two lists: states the platform will enter, and states it will not, with a reason. Typical docked-laptop Grok hosts in this class print Standby (S0 Low Power Idle) Network Connected as available, and S1 / S2 / S3 as unavailable because S0 low power idle is supported. Hybrid Sleep then says Standby (S3) is not available. Hibernate and Fast Startup may still list as available until those packs are applied. That output is a class, not a serial number. Do not paste a live dump with OEM reasons onto GitHub Pages.

LEXXII-Materialize-Forever is Interactive-only. S0ix can look “asleep” while the process table still has grok.exe. S3 freezes RAM and the Interactive session is gone until resume. Those are not the same liar. Do not install systemd to paper over an S0ix map. Do not mint a Vercel slug because Hybrid Sleep was grey. Do not paste live NLV next to a sleep-state dump. NLV stays off Pages.

What to run (plugged-in Grok desk)

  1. Elevated Command Prompt, session unlocked, brick in — powercfg /a. Same as powercfg /availablesleepstates. Do this before changing Sleep after, Hybrid Sleep, Hibernate, or Fast Startup.
  2. Split the two lists — Available is what the platform will enter. Unavailable is what it will not, with a reason. Firmware, hypervisor, S0ix-disables-S3, Hibernate not enabled, and “Standby (S3) is not available” are different sentences. Read the reason. Do not stop at “sleep is weird.”
  3. Classify the standby class — S0 Low Power Idle (Modern Standby / Connected Standby path) vs S3 (classic Suspend-to-RAM) vs both (rare). Network Connected vs Network Disconnected on the S0ix line is NIC policy during idle, not a different ACPI letter. Then open the sibling that matches the class.
  4. Do not “fix” an honest unavailable — Hybrid Sleep unavailable because S3 is unavailable is expected on S0ix-only firmware. S1 and S2 unavailable on a 2024+ laptop is expected. Hibernate available after you wanted it off is the Hibernate Off pack, not a BIOS flash. Fast Startup available means Hibernate is still on.
  5. Re-query after a real policy click — /h off should move Hibernate and Fast Startup to unavailable. CSEnabled work is a different page and can brick Modern Standby networking — do not do it because this dump listed S0ix. Save the text locally. Do not publish it. Do not paste auth.json next to that output.
powercfg /a
powercfg /availablesleepstates
powercfg /a | more

The alias is /a. There is no GUID to unhide. There is no AC vs DC index. The map is per machine, per firmware, per hypervisor. A Hyper-V / WSL2 / VBS host can add “The hypervisor does not support this standby state” under Hybrid Sleep even when S3 is already gone. That is a reason line, not a license to install systemd. Event Viewer and sleepstudy are history. This dump is capability. Keep OEM strings off Pages.

How it splits from the other playbooks

  • Sleep vs forever — timeouts, Interactive-only, result 267009, Modern Standby as a behavior. This page is the firmware map that tells you whether that behavior is S0ix or S3.
  • CSEnabled — a registry hammer. This dump listing S0ix is not permission to flip CSEnabled.
  • Sleep after — STANDBYIDLE minutes. The map says which sleep those minutes enter.
  • Hybrid Sleep — HYBRIDSLEEP setting. Requires S3. This page tells you if the setting can exist.
  • Hibernate Off — powercfg /h off. Re-run /a after that click.
  • Fast Startup — hybrid shutdown. Requires Hibernate.
  • sleepstudy — S0ix history HTML. Capability is this page; history is that one.
  • /energy — 60-second trace. Not a state map.
  • /lastwake — who yanked the last sleep. Not which states exist.
  • This page — read powercfg /a before those clicks, then open the sibling that matches the available list.

Soak test (what "passes" means)

  1. Run powercfg /a on AC with the session unlocked. You get two lists and at least one standby class (S0ix or S3). Empty both-lists is a fail of the command, not a reason to install systemd.
  2. If S0 Low Power Idle is available and S3 is unavailable because S0 low power idle is supported: classify as Modern Standby. Do not hunt S3. Lid and Sleep after still need their own packs, but they are S0ix packs.
  3. If S3 is available and S0ix is not: classify as classic sleep. Hybrid Sleep is allowed to be a real row. Do not treat missing S0ix as a broken laptop.
  4. After powercfg /h off, re-run /a. Hibernate and Fast Startup should be unavailable. If Hibernate is gone and Fast Startup remains, the Fast Startup pack is still the liar — not this map.
  5. Hybrid Sleep unavailable solely because S3 is unavailable is a pass of this forensic, not a fail of Hybrid Sleep. Do not Apply Energy recommendations to force it.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the firmware grew S3. Host-forever is the named Windows task. Grok in-session schedulers still expire in 7 days even when durable. Keep the dump off Pages.

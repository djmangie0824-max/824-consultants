Processor minimum state vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the powercfg /requests page, and not a High performance plan essay. Sleep-vs-forever sets timeouts. Requests names a holder. This page is the remaining CPU floor: Power Options → Processor power management → Minimum processor state. Balanced AC defaults that row to 5%. Windows is allowed to drop frequency so an Interactive Grok CLI looks hung. Task Scheduler still shows Ready.

Download markdown powercfg /requests first Sleep vs forever

The problem

The sleep-vs-forever pack already tells you plugged-in sleep is not 5–20 minutes. powercfg /requests already tells you to name DISPLAY / SYSTEM / AWAYMODE holders. That work can be done and the TUI still looks frozen. Balanced Minimum processor state on AC is 5 percent. That is PROCTHROTTLEMIN. Windows may drop frequency and park work so grok.exe starves while schtasks still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The floor was 5 percent.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. The CPU policy is the liar. Do not install systemd to paper over a 5% floor. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide three other forever-loop bugs.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here.
  2. Confirm powercfg /requests is not a named holder — if DISPLAY, SYSTEM, or AWAYMODE is not None, that is powercfg /requests, not this page.
  3. Power Options → Change plan settings → Change advanced power settings → Processor power management → Minimum processor state — set Plugged in to 100%. On battery may stay 5% if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave Maximum processor state at 100% on AC — this page does not cap the ceiling. Do not drop Maximum to save a watt.
  5. Leave the Balanced (or current) plan in place — this page is one processor knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak — query the processor subgroup. 100 on AC is the pass. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_PROCESSOR
powercfg /a

SUB_PROCESSOR is the processor subgroup. PROCTHROTTLEMIN is Minimum processor state. 100 on AC is the pass for this desk. If the row is missing, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. Hidden is not the same as 100. Core parking (CPMINCORES) is a sibling, not this click. System cooling policy is a sibling, not this click.

How it splits from the other playbooks

  • Sleep vs forever — Modern Standby, Interactive-only logon, result 267009 still-running as a sleep tell. This page is the awake CPU floor.
  • powercfg /requests — DISPLAY / SYSTEM / AWAYMODE holders. A named process, not a percent floor.
  • When sharing media — one policy that can create a holder. Not PROCTHROTTLEMIN.
  • Allow wake timers — RTC if sleep still happened. Not a frequency floor.
  • Core parking / Intel Speed Shift — sibling processor rows. Not this click. Do not invent a registry paste on this page.
  • This page — AC Minimum processor state so Balanced 5% cannot starve an Interactive Grok CLI while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input. A session that paints but never completes a tool call because the floor is 5% is a fail on this page.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a 5% floor is not forever.
  4. Maximum processor state still 100% on AC. If someone dropped the ceiling, restore it. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof the floor is already 100.

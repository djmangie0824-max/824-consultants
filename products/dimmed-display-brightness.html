The problem

The idle-dim timer pack already tells you plugged-in Dim display after is 0 (Never). That is the preferred pass. Some images hide VIDEODIM after unhide. Some operators leave five minutes because an OLED lid “should rest.” Either way the lid still looks dead after idle. Display settings still lists both screens. The dock does not re-enumerate. First input does not handshake. The named task still prints Ready and last result 267009 (still-running). The operator buys another DP lead. A percent floor napped the backlight after the timer, or instead of the timer.

This is not Sleep. This is not VIDEOIDLE. This is not VIDEOCONLOCK. This is not VIDEODIM. A black panel with a handshake is an off timer — those are the other two pages. A drop to a dimmed level with both screens still listed is either the timer or this floor. If VIDEODIM is already 0 on AC, this row does not fire. Leave it. Do not cargo-cult 100% as a second Never. If VIDEODIM still fires, or the GUID for the timer is missing after unhide, the remaining honesty is this percent: 100 on AC so idle-dim cannot look like a dead lid. Do not install systemd to paper over 50%. Do not mint a Vercel slug because a lid looked asleep. Do not buy another DP cable until you have queried both the timer and the floor. How it splits from the other playbooks

  • Dim display after — idle-dim timer (VIDEODIM). Zero that first. This page is the nits floor after it fires.
  • Turn off display after — unlocked VIDEOIDLE. Panels black. DP/HDMI drop. Not a floor.
  • Console lock display off — lock-screen VIDEOCONLOCK. Same drop. Not a floor.
  • Display brightness on AC — leftover working percentage from the first second. Not a timer floor.
  • Enable adaptive brightness — ALS hunt when the room changes. Not a percent floor after idle minutes.
  • DisplayPort cable sit/stand — slack and latch. A real yank. Not a timer floor.
  • This page — AC Dimmed display brightness = 100 so a leftover 50% floor cannot make a live, enumerated lid look dead after the idle-dim timer still fires. The floor is not the timer. Dim is still not a DP unplug.

Soak test (what "passes" means)

  1. Sleep, lid, VIDEOIDLE, and VIDEOCONLOCK already honest. Prefer VIDEODIM 0. If VIDEODIM is already 0, this soak is a skip, not a red fail. The floor does not fire.
  2. When the timer still fires: leave the desk idle past the dim minutes. Lid closed, dedicated NIC plugged, dual ultrawide up. Laptop lid stays at working nits, not half. Display settings still shows the same screens. No dock re-plug. First input does not handshake.
  3. The floor is not the timer. Dim is still not a DP unplug. Fail this soak only if the dimmed percent was the liar. A black-then-handshake is VIDEOIDLE or VIDEOCONLOCK. A drop that recovers when you zero VIDEODIM is the timer page, not this one. Do not buy a DP cable because the laptop lid looked dark.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a half-nits lid is not forever if this floor is still 50 and the timer still fires. Host-forever on this Windows profile is that named task. Grok in-session schedulers still expire in 7 days even when durable — recreate them if missing. Do not claim the Windows task is a Linux systemd unit.
  5. GUID still 100 on AC if this page applied. If someone set 50 to “save the OLED lid,” restore 100 on this class of operator desk, or zero VIDEODIM instead. Do not “fix” it by switching the whole plan to High performance.

AHCI Link Power Management vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB 3 Link Power Management page, not the PCI Express ASPM page, and not a “Turn off hard disk after” essay. SuperSpeed U1/U2 is USB. ASPM is PCIe. This page is the remaining SATA/AHCI link: Power Options → Hard disk → AHCI Link Power Management - HIPM/DIPM. HIPM+DIPM can park the link after idle. A SATA boot disk, optical, or fallback HDD then looks gone. Task Scheduler still shows Ready.

Download markdown USB 3 LPM first PCIe ASPM

The problem

The USB selective suspend, USB 3 LPM, and PCIe ASPM packs already tell you to keep SuperSpeed and PCIe links awake on AC. That work can be done and a ship still stalls on disk. Balanced AHCI Link Power Management - HIPM/DIPM on AC is often HIPM+DIPM. Host-initiated and device-initiated link power drop the SATA PHY. The next Git object, Pages payload, or Grok session write waits on a link that went to Partial/Slumber. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the NVMe died. A SATA link napped.

This is not USB. This is not PCIe ASPM. powercfg /a still reports the same standby type. Requests can still be None. The AHCI link policy is the liar. Do not install systemd to paper over HIPM. Do not mint a Vercel slug because a disk blinked. Do not buy another NVMe enclosure until the SATA row is honest. An NVMe-only host that does not expose this row is a skip, not a registry paste.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever. If the desk still intends to sleep every idle, stop here.
  2. Confirm USB 3 LPM and PCIe ASPM are already Off on AC — if those rows still allow U1/U2 or ASPM, that is USB 3 LPM or PCIe ASPM, not this page.
  3. Power Options → Change plan settings → Change advanced power settings → Hard disk → AHCI Link Power Management - HIPM/DIPM — set Plugged in to Active. On battery may stay HIPM or HIPM+DIPM if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave HIPM-only and DIPM-only alone on AC — Active is no link power management. HIPM still lets the host park the PHY. That is not the AC pass for this desk.
  5. Leave “Turn off hard disk after” as a sibling — that is idle timeout / spin-down, not link power. Do not treat 20 minutes as this click. If the AHCI row is already Active and a mechanical disk still sleeps, that is a different page. Do not invent it here.
  6. Leave the Balanced (or current) plan in place — this page is one hard-disk knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  7. Confirm, then soak — query the disk subgroup. Active on AC is the pass. If the alias is missing, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_DISK
powercfg /a

SUB_DISK is the hard-disk subgroup. The AHCI LPM row is HIPM/DIPM (aliases vary by edition; look for HIPM, DIPM, or “AHCI Link Power Management”). Active on AC is the pass for this desk: no host-initiated and no device-initiated SATA link power. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as Active. If powercfg also omits it, this firmware did not expose the knob — stop; do not invent a registry hack on a public page. USB 3 LPM is SuperSpeed, not this click. PCIe ASPM is the dock/NVMe bus, not this click. Disk idle timeout is a sibling, not this click.

How it splits from the other playbooks

  • USB 3 Link Power Management — SuperSpeed U1/U2 on the dedicated NIC. Not SATA.
  • PCI Express Link State Power Management — ASPM on Thunderbolt/USB4/NVMe. Not AHCI.
  • USB selective suspend — the USB device-power policy. Not the SATA PHY.
  • NVMe enclosure — hardware fallback box. Buy after the link policies are honest, not instead of them.
  • Hard disk idle timeout — “Turn off hard disk after.” Spin-down minutes, not HIPM/DIPM. Sibling, not this click.
  • This page — AC AHCI Link Power Management = Active so HIPM/DIPM cannot park a SATA link while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. USB 3 LPM already Off on AC if the row exists. PCIe ASPM already Off on AC if the row exists. Otherwise this soak is lying about the bus.
  2. Leave the desk idle 30 minutes, lid closed, dedicated NIC plugged. The Grok TUI still accepts input. Device Manager / disk Present does not flap. One silent 2-second stall on the first write after idle is a fail if the AHCI row exists and was not Active.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a napping SATA PHY is not forever.
  4. AHCI LPM still Active on AC. If someone set HIPM+DIPM to “save the SSD,” restore Active. Do not “fix” it by switching the whole plan to High performance.
  5. Missing row + NVMe-only host = skip, not a red soak. Do not invent HIPM in the registry to make this page apply.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the SATA link stayed up.

USB 3 Link Power Management vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB selective suspend page, not the PCI Express ASPM page, and not the USB Ethernet buy guide. Selective suspend is device-level D3 / U3. ASPM parks a PCIe/USB4 tunnel. Ethernet is the NIC SKU. This page is the SuperSpeed link-state policy: Power Options → USB settings → USB 3 Link Power Management. U1 and U2 can drop a dedicated USB NIC while the laptop still looks awake and Task Scheduler still shows Ready.

The problem

The USB selective suspend pack already tells you to set that row to Disabled on AC and to uncheck Allow the computer to turn off this device to save power on the hub that actually carries Ethernet. That work can be done and the NIC still flaps after idle. The remaining USB knob is not another Device Manager checkbox. It is USB 3 Link Power Management.

USB 3 SuperSpeed links have four states. U0 is active. U1 is a fast idle (tens of microseconds to wake). U2 is a slower idle (milliseconds). U3 is device suspend — that is the selective-suspend layer, already covered. Balanced defaults USB 3 LPM to Moderate or Maximum power savings, which permits U1 and often U2 while the session is still interactive. Cheap ASIX / Realtek USB NICs and many USB-C hubs mishandle U2. The adapter looks unplugged for a second, TCP resets, GitHub MCP vanishes, a git push hangs at credentials, and LEXXII-Materialize-Forever still claims Ready. The operator thinks Git is missing. The SuperSpeed link left.

This happens while the machine is awake. It is not Modern Standby. It is not IEEE 802.3az. It is not ASPM on the Thunderbolt controller. Do not install systemd to paper over U2. Do not mint a Vercel slug because the NIC blinked.

What to change (plugged-in Grok desk)

  1. Confirm the USB suspend layer is already done — Power Options → USB settings → USB selective suspend → Plugged in = Disabled. Hub that carries Ethernet already unchecked for Allow the computer to turn off this device to save power. See that playbook. If that is still Enabled, stop here.
  2. Power Options → Change plan settings → Change advanced power settings → USB settings → USB 3 Link Power Management — set Plugged in to Off. On battery may stay Moderate power savings if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  3. Leave the Balanced (or current) plan in place — this page is one USB knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  4. Confirm, then soak — query the USB subgroup. Off on AC is the no-power-saving index, not Moderate or Maximum. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_USB
powercfg /a

SUB_USB is the USB subgroup. USB 3 Link Power Management is a sibling of USB selective suspend on SKUs that expose it. Off on AC is the pass for this desk. If the USB 3 LPM row is missing, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. Hidden is not the same as Off. Do not unhide it with a cargo-cult GUID paste from a forum.

How it splits from the other playbooks

  • USB selective suspend — device-level D3 / U3 and the hub Power Management checkbox. That pack deferred this SuperSpeed row on purpose.
  • PCI Express Link State Power Management — ASPM L0s/L1 on a USB4/Thunderbolt tunnel or NVMe. Not a SuperSpeed U1/U2 policy.
  • Energy Efficient Ethernet — IEEE 802.3az / Green Ethernet on the adapter PHY. The NIC stays Present.
  • Network connectivity in Standby — NIC policy during S0ix, after the laptop actually slept.
  • Sleep vs forever — Modern Standby, Interactive-only logon, result 267009 still-running.
  • USB Ethernet review — hardware criteria, SKU pending. Not a power-plan row.
  • This page — SuperSpeed U1/U2 so a USB NIC or hub does not vanish while the named task still looks Ready.

Soak test (what "passes" means)

  1. USB selective suspend already Disabled on AC. Hub Power Management already honest. Lid close already Do nothing on AC. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The NIC stays Present. One silent re-enumerate is a fail on this page.
  3. Ping out the USB NIC. One silent gap is a fail — but if USB suspend is still Enabled, it is the USB suspend page, not this one. If the NIC stays Present and only speed downshifts, it is EEE, not this one.
  4. USB-C hub downstream devices (if that is the Ethernet path) stay enumerated. A hub that blinks and comes back is a fail.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a napping SuperSpeed link is not forever.
  6. No fourth Grok TUI. Last result 267009 is still-running, not an LPM bug.

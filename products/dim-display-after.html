Dim display after vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Turn off display after page, not the Console lock display off page, and not a DisplayPort cable review. VIDEOIDLE blacks unlocked idle. VIDEOCONLOCK blacks the lock screen. The cable is slack and latch. This page is the remaining idle-dim timer: Power Options → Display → Dim display after. Five minutes on AC still drops laptop nits. Dual ultrawide stay listed. Task Scheduler still shows Ready. Dim is not a DP unplug.

The problem

The display idle pack already tells you plugged-in Turn off display after is 0 (Never). The lock-screen timer can already be 0. Sleep and lid can already be honest. That work can be done and the operator still thinks video died after a few idle minutes. Balanced Dim display after on AC is often 5 minutes. The laptop lid drops to the dimmed level. External DP/HDMI keep their OSD. Display settings still lists both screens. The dock does not re-enumerate. The Grok TUI is still a process. The named task still prints Ready and last result 267009 (still-running). The operator buys another DP lead. A timer napped the backlight. The link never dropped.

This is not Sleep. This is not VIDEOIDLE. This is not VIDEOCONLOCK. A black panel with a handshake and a dock re-enumerate is an off timer — those are the other two pages. This page is dim, still enumerated. powercfg /a still reports the same standby type. Requests can still be None. VIDEOIDLE can still be 0. VIDEOCONLOCK can still be 0. The idle-dim policy is the liar. Do not install systemd to paper over 5 minutes. Do not mint a Vercel slug because a lid looked asleep. Do not buy another DP cable until this row is 0 on AC and you have watched Display settings during the dip. Dim is not a DP unplug.

What to change (plugged-in Grok desk)

  1. Confirm the off-timer layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Turn off display after is 0 on AC. Console lock display off is 0 on AC (or the GUID was missing after unhide — that is a skip, not a leftover 60 seconds). See turn-off-display-after and console-lock-display-off. If VIDEOIDLE is still 5–10 minutes, stop here. A black-then-handshake is those pages.
  2. Unhide the row if it is missing — Dim display after is ATTRIB_HIDE on many consumer images, and Windows 11 often omits it from the GUI even when powercfg still has the GUID. Missing from Display before this step is expected, not a skip.
  3. Power Options → Change plan settings → Change advanced power settings → Display → Dim display after — set Plugged in to 0 minutes (Never). On battery may stay 2–5 if this laptop actually travels. A desk that never unplugs should not idle-dim the operator TUI.
  4. Leave Turn off display after and Console lock display off alone on this click — VIDEOIDLE and VIDEOCONLOCK are blackouts and link drops. VIDEODIM is an idle nits cut. Do not treat 0 on one as 0 on the other. Dim is not off.
  5. Leave Display brightness, Enable adaptive brightness, Energy saver, and Dimmed display brightness alone on this click — VIDEONORMALLEVEL is the working percentage. ADAPTBRIGHT is the ALS hunt. Energy saver is the leaf overlay. Dimmed display brightness is the nits floor after this timer fires. Zeroing the timer is the pass; dragging the dimmed floor is not Never.
  6. Leave the Balanced (or current) plan in place — this page is one display knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO. Do not Apply all on Energy recommendations; that card can smash sleep and display timers.
  7. Confirm, then soak — query VIDEODIM. 0 on AC is the pass. If the alias is missing, query the GUID. If the GUID is missing after unhide, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg -attributes SUB_VIDEO 17aaa29b-8b43-4b94-aafe-35f64daaf1ee -ATTRIB_HIDE
powercfg /query SCHEME_CURRENT SUB_VIDEO VIDEODIM
powercfg /query SCHEME_CURRENT SUB_VIDEO 17aaa29b-8b43-4b94-aafe-35f64daaf1ee
powercfg /setacvalueindex SCHEME_CURRENT SUB_VIDEO VIDEODIM 0
powercfg /setactive SCHEME_CURRENT
powercfg /a

SUB_VIDEO / VIDEODIM is Dim display after (GUID 17aaa29b-8b43-4b94-aafe-35f64daaf1ee). The AC index is seconds in the query; the GUI speaks minutes. 0 is Never. 300 remaining on AC is 5 minutes — Balanced laptop default, not a pass. Apply with /setactive or the GUI change does not take. Query by GUID if the alias is missing. Unhide is not a registry paste; powercfg -attributes … -ATTRIB_HIDE is the documented reveal. If powercfg still omits the GUID after that, this edition did not expose the knob — stop; do not invent an idle-dim hack on a public page. VIDEOIDLE is unlocked off, not this click. VIDEOCONLOCK is lock-screen off, not this click. STANDBYIDLE is Sleep after, not this click. Dimmed display brightness is the floor, not the timer. External DP/HDMI often ignore this Windows dim and keep their own OSD — a dim lid with both screens still listed is this click, not a handshake. Dim is not a DP unplug.

How it splits from the other playbooks

  • Turn off display after — unlocked VIDEOIDLE. Panels black. DP/HDMI drop. Dock re-enumerates. Not idle-dim.
  • Console lock display off — lock-screen VIDEOCONLOCK. Same drop, lock-screen timer. Not idle-dim.
  • Enable adaptive brightness — ALS hunt when the room changes. Not minutes of idle.
  • Display brightness on AC — leftover working percentage from the first second. Not a timer.
  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not panel nits.
  • Lid close Do nothing — lid action. Not Display minutes.
  • powercfg /requests — a named holder pinning DISPLAY. Not VIDEODIM.
  • DisplayPort cable sit/stand — slack and latch. A real yank. Not a timer.
  • This page — AC Dim display after = 0 so idle minutes cannot cut nits on a live, enumerated panel while the named task still looks Ready. Dim is not a DP unplug.

Soak test (what "passes" means)

  1. Sleep, lid, VIDEOIDLE, and VIDEOCONLOCK already honest. Otherwise this soak is lying about an off-timer blackout.
  2. Leave the desk idle past the old dim minutes (10 minutes covers a leftover 5). Lid closed, dedicated NIC plugged, dual ultrawide up. Laptop lid (or any Windows-driven backlight) stays at the operator-set working level — not a surprise drop to the dimmed floor. Display settings still shows the same screens. No dock re-plug. First input does not handshake.
  3. Dim is not a DP unplug. Fail this soak only if the idle-dim timer was the liar. A black-then-handshake on first input with a dock re-enumerate is a VIDEOIDLE or VIDEOCONLOCK fail, not this page. Do not buy a DP cable because the laptop lid looked dark.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a dimmed lid is not forever if VIDEODIM is still 300. Ready + 267009 with a dead DP link is the off-timer pages, not this one. Host-forever on this Windows profile is that named task. Grok in-session schedulers still expire in 7 days even when durable — recreate them if missing. Do not claim the Windows task is a Linux systemd unit.
  5. VIDEODIM still 0 on AC. If someone set 5 minutes to “save the OLED lid,” restore 0 on this class of operator desk. Do not “fix” it by switching the whole plan to High performance.
  6. Missing GUID after unhide = skip, not a red soak. Do not invent the idle-dim value in the registry to make this page apply. Then check ALS and Display brightness; those siblings can still make a live panel look dead.
  7. No fourth Grok TUI. Last result 267009 is still-running, not proof the idle-dim timer is already Never.

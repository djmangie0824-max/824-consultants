powercfg /energy vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the /sleepstudy page, not the /lastwake forensic, not /requests, and not multimedia timer resolution. Sleep study is Connected Standby session history. /lastwake names who yanked the last sleep. /requests names DISPLAY and SYSTEM holders while the session is already awake. Timer-resolution is the leftover 1 ms timeBeginPeriod layer. This page is the remaining 60-second energy-efficiency HTML: powercfg /energy. It is a live trace, not a CS table. The report stays on disk. It does not go on GitHub Pages. The 60-second trace is not a CS session list. The HTML is not public property.

The problem

LEXXII-Materialize-Forever is Interactive-only. Lid can already be Do nothing on AC. Sleep after can already be Never. Wake timers can already be Enable. Task Scheduler still prints Ready. Last result 267009 is still-running. The operator still thinks Grok died. Sleep study may already show no CS session in the missed hour. /requests may already be empty. The remaining liar is often an energy-efficiency Error that only a 60-second elevated trace names: an Outstanding Timer Request, a USB device that will not enter selective suspend, PCI Express ASPM left on Maximum power savings, a Power Policy row that still has a 5-minute sleep idle while Settings looks honest.

powercfg /energy is that trace. Default duration is 60 seconds. It must run elevated. It writes energy-report.html. Errors, Warnings, and Information are three different buckets. An Error is a named leftover. A Warning is often the Balanced default, not a fail. Information is context. Device instance paths in that HTML are local forensics. Do not Apply all on Settings → Energy recommendations. Do not paste the report next to live NLV. NLV stays off Pages.

This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd because USB Selective Suspend printed a Warning. Do not spawn a fourth Grok TUI because a 60-second sample listed a HID that must stay awake on a docked desk.

What to run (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in Sleep after is not 5–20 minutes. Lid close on AC is Do nothing if that is the desk policy. See sleep-vs-forever.
  2. Confirm this is not a CS-history question — if the missed hour was a closed-lid Modern Standby freeze, run sleep study first. /energy does not list CS sessions.
  3. Confirm this is not a now holder — if the fan is up and the session never idles, run /requests first. /energy is a 60-second sample, not a live pin list.
  4. Generate locally — elevated Command Prompt, desk idle but awake, dual ultrawide listed, dedicated NIC up: powercfg /energy /duration 60 /output %USERPROFILE%\energy-report.html. Wait the full sixty seconds. Open the HTML on this host. Do not commit it. Do not drag it onto Pages.
  5. Classify, then act — Errors vs Warnings vs Information. Named Errors go to the sibling that owns that name. Do not Apply all. Do not paste auth.json next to that HTML.

Soak test (what "passes" means)

  1. Sleep, lid, and powercfg /a already honest. Otherwise this soak is lying about which state ran.
  2. Plugged in. Session awake. Dual ultrawide listed. Dedicated NIC up. Elevated /energy /duration 60 to a path you own.
  3. Errors that name a timer requester, USB device, ASPM, or a 5-minute sleep idle are this layer. Act on the sibling. Re-run the 60-second trace. Those Errors gone is the pass.
  4. Warnings-only on a desk whose named task last-run still advanced is a skip, not a red fail. Do not Apply all. Do not spawn a fourth Grok TUI.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 is still-running, not proof /energy was clean. Grok in-session schedulers still expire in 7 days even when durable.
  6. energy-report.html is still local. If it appeared on GitHub Pages, that is a fail of this pack — delete it from origin. Device paths are not public property.
  7. Missing elevation is a rerun, not a skip of the layer. A 60-second trace is not sleep study.

The problem

Headless Windows grok CLI sessions do not always see the in-product scheduler store the operator TUI sees. The list comes back empty. Early loops treated that as “host-forever is dead” and recreated hourly + daily + 30m + 2h lanes every pulse. That is token suicide. Grok scheduler tasks auto-expire after 7 days even when durable — that sentence stays true. It does not authorize minting copies of IDs that still exist in the product. Extra TUI windows do not fix isolation. They split the same quota.

Host-forever on this profile is Windows Task Scheduler: LEXXII-Materialize-Forever, LEXXII-Pages-Heal, LEXXII-Ship, LEXXII-UMI, LEXXII-BI, LEXXII-Compound. Those tasks are Interactive-only. Logged-off is not 24/7. That honesty lives on the create-the-task and sleep-vs-forever packs. This page is only the Grok-list false-empty.

What to change

  1. Call scheduler_list once — do not recreate first and list later.
  2. If the list is empty — write HEAL.log with UTC time, Pages HTTP, scheduler_list empty isolation skip recreate, and NLV private. Do not call scheduler_create.
  3. If the list is non-empty — recreate only a named lane that is actually missing. Keep pulse 5m / 15m. Do not restore hour and 2-hour waits. Stop-burn is retired.
  4. Confirm Windows tasks — schtasks /Query /TN LEXXII-Materialize-Forever still Enabled. Host-forever is that task, not a Grok ID, not systemd.
  5. Do not spawn a fourth Grok TUI — extra TUIs do not reveal the isolated list. They split quota. Prefer the headless run already open.

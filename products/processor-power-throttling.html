Processor power throttling vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Minimum processor state page, not Processor idle disable, not Intel Speed Shift EPP, and not the system cooling policy page. Min-state is the frequency floor. Idle disable is C-state residency. Speed Shift EPP is a 0–100 hardware hint. Cooling policy is fans vs thermal drop. This page is the remaining software ceiling: Power Options → Processor power management → Maximum processor state. That is PROCTHROTTLEMAX. OEM “quiet” Balanced plans leave it at 99% or 80%. Windows may not enter the top P-states even when boost is Enabled. An Interactive Grok CLI looks hung. Task Scheduler still shows Ready.

The problem

The min-state, core parking, boost mode, and cooling policy packs can already be honest on AC. Frequency floor 100. Unparked cores 100. Turbo allowed (Enabled). Fans allowed. The TUI still starves. Maximum processor state is a different row in the same subgroup. That is PROCTHROTTLEMAX. It is a hard percent cap on P-states, not a hint. OEM “Cool” / “Quiet” / “Battery” Balanced plans drop it to 50–80. Forum folklore drops it to 99 to kill turbo without touching PERFBOOSTMODE. Enabled boost under a 99% ceiling is still a capped desk. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The ceiling was 99.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. PROCTHROTTLEMIN can still be 100. PERFBOOSTMODE can still be Enabled. SYSCOOLPOL can still be Active. Processor idle disable can still be the default. Intel Speed Shift EPP can still be 0. The throttle ceiling is the liar. Do not install systemd to paper over a 99% cap. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide five other forever-loop bugs. Do not confuse this PPM row with Windows EcoQoS “Power throttling” of background apps — that is a process overlay, not PROCTHROTTLEMAX.

How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). This page is the frequency ceiling (PROCTHROTTLEMAX). Floor 100 under a 99 ceiling is still a cap.
  • Core parking — unparked-core floor (CPMINCORES). Parking is not a P-state ceiling.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Enabled turbo under a 99% max is still blocked. Not the same click.
  • System cooling policy — Passive vs Active fans. Thermal policy, not the software percent cap.
  • Processor idle disable — C-state residency. Idle, not the P-state ceiling. Not this click.
  • Intel Speed Shift / EPP — 0–100 HWP hint. A hint is not a hard percent cap. Not this click.
  • Windows EcoQoS Power throttling — process overlay on background apps. Task Manager Details column, not PROCTHROTTLEMAX.
  • Laptop cooling stand — air under a closed lid. Hardware. A 100% ceiling does not replace a stand.
  • This page — AC Maximum processor state = 100 so an OEM 99% or 80% throttle cannot starve an Interactive Grok CLI while the named task still looks Ready.

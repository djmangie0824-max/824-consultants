Intel Graphics panel power saving vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Turn off display after page, not the Console lock display off page, and not the PCI Express Link State Power Management page. VIDEOIDLE is Windows unlocked idle. VIDEOCONLOCK is the lock-screen timer. ASPM is the PCIe root port. This page is the remaining GPU encoder: Intel Graphics Power Plan and Intel panel / display power saving. The iGPU parks DP/HDMI. Dual ultrawide vanish. Task Scheduler still shows Ready.

The problem

The display idle pack already sets plugged-in Turn off display after to 0. The console lock pack already sets the lock-screen timeout to 0. The ASPM pack already sets PCI Express Link State Power Management to Off on AC. That work can be done and dual ultrawide still go black after idle. Windows did not fire VIDEOIDLE. The session is still unlocked. The dock still has power. The Intel display engine decided the panel could nap.

On this class of laptop the Intel iGPU is often the display engine even when an NVIDIA chip is doing the 3D. Intel Graphics Settings injects its own Power Options subgroup. Balanced and Maximum Battery Life let render C-states, Display Power Saving Technology, and Panel Self-Refresh starve the DP/HDMI encoder. The dock treats a silent encoder as unplug. Windows rebuilds the desktop. LEXXII-Materialize-Forever still prints Ready and last result 267009 (still-running). The operator thinks VIDEOIDLE lied, or the DP lead failed. The GPU panel-power policy napped the link.

This is not Sleep. This is not unlocked Display minutes. This is not lock-screen minutes. This is not ASPM. powercfg /a still reports the same standby type. powercfg /requests can still be None. VIDEOIDLE can still be 0. The Intel subgroup is the liar. Do not install systemd to paper over an iGPU encoder. Do not mint a Vercel slug because a panel handshake retrained. Do not buy another DP cable until this Intel row is Maximum Performance on AC.

What to change (plugged-in Grok desk)

  1. Confirm the Windows display and PCIe layers are already done — Turn off display after is 0 on AC. Console lock display off is 0 on AC if the GUID exists. PCI Express Link State Power Management is Off on AC. See turn-off-display-after, console-lock-display-off, and pcie-link-state-power. If VIDEOIDLE is still 5–10 minutes, stop here. That black panel is not this click.
  2. Confirm an Intel display adapter exists — Device Manager → Display adapters. Intel UHD, Iris, Arc, or HD Graphics must be Present. Hybrid NVIDIA + Intel still uses this page when Intel owns the outputs. NVIDIA-only or AMD-only SKUs skip. Do not disable the Intel adapter. Do not uninstall the driver.
  3. Power Options → Change plan settings → Change advanced power settings → Intel(R) Graphics Settings → Intel(R) Graphics Power Plan — set Plugged in to Maximum Performance. On battery may stay Balanced or Maximum Battery Life if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube. If the Intel subgroup is missing, skip this GUI row and use Command Center in the next step.
  4. Intel Graphics Command Center / Intel Graphics Software → System → Power — on AC, turn Display Power Saving Technology Off. Turn Panel Self-Refresh Off if the row exists. Legacy Intel HD Graphics Control Panel names the same idea Panel Power Saving — Off / 0 on AC. Do not hunt NVIDIA Power management mode on this page.
  5. Leave the Balanced (or current) Windows plan in place — this page is one Intel driver knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak — query the Intel subgroup. Maximum Performance on AC is the pass when the GUID exists. If the GUID is missing and Command Center also has no Power page, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.

The Intel subgroup GUID is the driver-injected Intel(R) Graphics Settings block. The setting GUID is Intel(R) Graphics Power Plan. AC index 2 is Maximum Performance. 0 is Maximum Battery Life. 1 is Balanced. Those are Intel’s plan values, not VIDEOIDLE seconds. Apply with /setactive or the GUI change does not take. If powercfg omits 44f3beca-…, this driver did not inject the subgroup — stop at Command Center; do not invent a registry paste on a public page. VIDEOIDLE is unlocked Display minutes, not this click. VIDEOCONLOCK is lock-screen minutes, not this click. SUB_PCIEXPRESS is ASPM, not this click.

How it splits from the other playbooks

  • Turn off display after — Windows VIDEOIDLE. OS Display minutes. Not the Intel encoder.
  • Console lock display off — Windows VIDEOCONLOCK. Lock-screen timer. Not GPU panel power.
  • PCI Express Link State Power Management — ASPM on the root port. A dock tunnel nap. Not the display pipeline.
  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not panel power.
  • Lid close Do nothing — lid action. Not an iGPU C-state.
  • DisplayPort cable sit/stand — slack and latch. Not a driver power plan.
  • Dock multi-monitor — hardware. Buy after the encoder is honest, not instead of this click.
  • This page — Intel Graphics Power Plan Maximum Performance on AC, DPST / Panel Self-Refresh / Panel Power Saving Off, so the iGPU cannot drop DP/HDMI while the named task still looks Ready.

Soak test (what "passes" means)

  1. VIDEOIDLE already 0 on AC. Console lock already 0 on AC if the GUID exists. ASPM already Off on AC. Lid close already Do nothing on AC. Otherwise this soak is lying about Windows display and PCIe.
  2. Leave the desk idle 30 minutes, session unlocked, lid closed, dedicated NIC plugged, dual ultrawide up. Panels stay on. Display settings still show both screens. A black-then-handshake on first input is a fail if Intel Graphics Power Plan was not Maximum Performance on AC, or if Display Power Saving Technology was still on.
  3. Device Manager still shows the Intel adapter Present. A brief yellow bang then recover on the Intel GPU is a fail on this page, not a cable fail.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a dead DP link is not forever.
  5. The Intel AC index still 2 when the GUID exists. If someone set Balanced to “save the iGPU,” restore Maximum Performance on this class of operator desk. Do not “fix” it by switching the whole Windows plan to High performance.
  6. No Intel adapter = skip, not a red soak. Missing Intel subgroup + no Command Center Power page = skip, not a registry paste.
  7. No fourth Grok TUI. Last result 267009 is still-running, not proof the encoder stayed awake.

Allow Away Mode vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the When sharing media page and not the powercfg /requests diagnostic. Sharing is the Multimedia row that can ask for fake-sleep. Requests names who is holding the AWAYMODE bucket right now. This page is the Sleep permission: Power Options → Sleep → Allow Away Mode. That is AWAYMODE under SUB_SLEEP. On lets a Sleep verb become media-center fake-sleep. Interactive-only LEXXII-Materialize-Forever looks dead. Task Scheduler still shows Ready.

Download markdown Sharing media first Read the holders

The problem

The sharing-media pack already tells you not to set When sharing media to Prevent or “Allow the computer to enter Away Mode.” /requests already tells you to name a live AWAYMODE holder. That work can be done and fake-sleep still exists as a state. Balanced and OEM entertainment plans ship Allow Away Mode On. Windows then lists Away Mode under powercfg /a. Display goes dark. Fans, NIC, and the logged-on session stay up. The operator hunts wake timers for a sleep that never happened. schtasks still prints Ready and last result 267009 (still-running). Fake-sleep is not host-forever. It is a Media Center leftover.

Two objects, one word. Sharing media is a Multimedia value (Allow sleep / Prevent / enter Away Mode). This page is the Sleep policy that allows the fake-sleep state at all. A share request cannot enter Away Mode if Allow Away Mode is Off. Do not set this On to “keep the forever loop alive.” That pins a dark panel with the session still running. It does not fire the named hourly. Do not install systemd to paper over AWAYMODE. Do not mint a Vercel slug because the fans stayed up while the screen looked asleep.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever and lid-close.
  2. Confirm When sharing media is already Allow the computer to sleep on AC — not Prevent, not enter Away Mode. If that row is still the liar, that is sharing media, not this page.
  3. Power Options → Change plan settings → Change advanced power settings → Sleep → Allow Away Mode — set Plugged in to Off. On battery may stay On if this chassis is actually a media PC that travels. A Grok desk that never unplugs should not pretend it is a living-room recorder.
  4. Leave Sleep after, hybrid sleep, and Hibernate as their own pages — this click is one Sleep permission. Do not powercfg /hibernate off to hide it. Do not switch the plan to High performance.
  5. Leave the current plan in place — do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak — query the Sleep alias. Off on AC is the pass. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_SLEEP AWAYMODE
powercfg /a
powercfg /requests

SUB_SLEEP is the Sleep subgroup. AWAYMODE is Allow Away Mode. 0 = Off, 1 = On. Off on AC is the pass for this desk: Away Mode is not an available sleep state. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as Off. If powercfg also omits the alias, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. Idle /requests AWAYMODE = None is expected after Off. A leftover named holder is requests, not this row. Sleep after is a timeout, not this click. Hybrid sleep is a hiberfile, not this click.

How it splits from the other playbooks

  • When sharing media — Multimedia value that can request fake-sleep. This page is whether Sleep is allowed to enter that state.
  • powercfg /requests — who is holding the AWAYMODE bucket right now. Not a plan value.
  • Sleep vs forever — timeouts, Modern Standby, Interactive-only, result 267009 as a timeout tell.
  • Allow hybrid sleep — hiberfile then S3. Not fake-sleep with fans up.
  • Lid close Do nothing — the lid is not a Sleep key. Away Mode is not a lid policy.
  • Turn off display after — VIDEOIDLE. Dark panel with an honest awake session is not Away Mode.
  • This page — AC Allow Away Mode = Off so AWAYMODE cannot list fake-sleep as an available state while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. Sharing media already Allow sleep. Otherwise this soak is lying about which layer faked sleep.
  2. AWAYMODE AC index is 0. powercfg /a does not list Away Mode as available (policy, not firmware, is the tell when the alias exists).
  3. Idle session, no player, no Cast. powercfg /requests prints None under AWAYMODE.
  4. Display-off from VIDEOIDLE is not this page. Fans and session stay up and /a still lists Away Mode = this page is not done.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 after fake-sleep is not forever.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof Allow Away Mode is already Off.

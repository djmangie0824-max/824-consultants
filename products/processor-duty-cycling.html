Processor duty cycling vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Processor idle disable page (C-states / IDLEDISABLE), not Processor performance boost mode, not processor power throttling (EcoQoS / max-state catalog mix), and not Allow Throttle States (ACPI T-states / THROTTLING). This page is Power Options → Processor power management → Processor duty cycling. Alias PERFDUTYCYCLING. GUID 4e4450b3-6179-4e91-b8f1-5bb9938f81a1. Possible values: 0 Disabled, 1 Enabled. On this Yoga Balanced the measured pass is already Disabled on AC and DC. The short alias DUTYCYCLING is invalid on this SKU — use PERFDUTYCYCLING or the GUID.

The problem

Sibling processor knobs can already be honest on AC. Frequency floor named. Turbo allowed. Parking named. Idle policy named. Allow Throttle States already Off if that pack ran. Someone still “optimizes watts” by turning Processor duty cycling to Enabled. Enabled duty-cycles the package — modulated on/off — so an Interactive Grok CLI looks hung between bursts. grok.exe is alive. Task Scheduler still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The package was chopped.

This is not a C-state lie and not an ACPI T-state lie. IDLEDISABLE 0 still lets deep C. THROTTLING Automatic still allows clock-modulation T-states. This GUID is a separate allow for package duty cycling. Do not install systemd to paper over Enabled duty cycling. Do not mint a Vercel slug because the TUI paused while the package was off in the duty cycle. Do not switch the whole plan to High performance to hide ten other forever-loop bugs. Duty cycling is not idle and not T-states

LayerWhat it actually is
Processor idle disableC-state allow. IDLEDISABLE. 0 = Enable idle. 1 = Disable idle (stay C0). Package sleep, not on/off modulation.
Allow Throttle StatesACPI T-state allow. THROTTLING. 0 Off · 1 On · 2 Automatic. Clock duty cuts under a P-state.
Processor power throttling pageCatalog mix of max-state ceiling + EcoQoS process overlay. Filename collision. Not this GUID.
Processor performance boost modeTurbo P-state allow. PERFBOOSTMODE. Only while executing.
Processor duty cyclingPackage on/off modulation. PERFDUTYCYCLING. 0 Disabled · 1 Enabled. This page.

Enabled duty cycling looks like a hung TUI with a still-healthy scheduler. Disabled is the forever-desk pass on this host. Enabling it to “save watts” on a plugged-in Grok desk is a cargo-cult fail.

How it splits from the other playbooks

  • Processor idle disable — C-state allow/deny. Enable idle vs stay C0. Heat. Not package on/off duty cycling.
  • Allow Throttle States — ACPI T-states Off/On/Automatic. Clock modulation under a P-state. Different GUID.
  • Processor power throttling — max-state / EcoQoS catalog mix. Same English “throttling.” Different object.
  • Processor performance boost mode — turbo allow. Enabled turbo under Enabled duty cycling can still look hung between chops.
  • Processor idle time check — C-state sample window in microseconds. Not this click.
  • This page — confirm PERFDUTYCYCLING Disabled (0) on AC so package on/off modulation cannot stall an Interactive Grok CLI while the named task still looks Ready.

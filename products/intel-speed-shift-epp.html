Intel Speed Shift / energy performance preference vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Processor performance boost mode page, not the Minimum processor state page, not the core parking page, and not the system cooling policy page. Boost mode (PERFBOOSTMODE) is the turbo allow. Min-state (PROCTHROTTLEMIN) is the frequency floor. Parking (CPMINCORES) is the unparked-core floor. Cooling (SYSCOOLPOL) is fans vs throttle. This page is the remaining hardware hint: Intel Speed Shift (hardware-controlled P-states / HWP) still reads Processor energy performance preference. That is PERFEPP and, on hybrid packages, PERFEPP1. The scale is 0–100. It is not a percent of clocks. 0 = performance. 100 = efficiency. Typical Balanced AC is 60–70. Silicon still prefers watts between Grok bursts. Task Scheduler still shows Ready.

The problem

The four sibling knobs can already be honest on AC. Frequency floor 100. Unparked cores 100. Turbo allowed (Enabled). Fans allowed (Active). The TUI still starves between tokens. Intel Speed Shift lets the package pick its own P-state. Windows does not request each P-state on that path. Windows hands the silicon an Energy Performance Preference. Balanced leaves that hint at 60–70 on AC. An Interactive Grok CLI is bursty: a paint, a wait, a paint. HWP treats the wait as idle. Efficiency bias wins. Clocks sit mid-range. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died and opens a fourth TUI. EPP was 60.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. PERFBOOSTMODE can still be Enabled — that only permits turbo. Speed Shift still decides whether the package takes it. Minimum processor state 100% of an efficiency-biased HWP hint is still a slow desk. Do not install systemd to paper over EPP 60. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide four other forever-loop bugs. Do not paste a registry EPP hack if the alias is missing — stop.

  3. Query both Speed Shift aliases before you write — PERFEPP is Processor energy performance preference (typical P-core / package hint). PERFEPP1 is Processor energy performance preference for Processor 1 (typical hybrid / E-core class). If a row is missing from the GUI, query with powercfg anyway — hidden is not the same as 0. How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). This page is the Speed Shift energy-performance hint the hardware reads above that floor (PERFEPP).
  • Core parking — unparked-core floor (CPMINCORES). Parking is not EPP. Unparked cores can still run efficiency-biased P-states.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Enabled turbo with EPP 60 still prefers watts between bursts. Not the same click.
  • System cooling policy — Passive vs Active fans (SYSCOOLPOL). Thermal policy, not the HWP hint.
  • Laptop cooling stand — air under a closed lid. Hardware. EPP 0 does not replace a stand. A stand does not replace EPP 0.
  • Heterogeneous thread scheduling — sibling processor row. Core-class scheduling, not this click. Do not invent a registry paste on this page.
  • This page — AC Intel Speed Shift Energy Performance Preference = 0 so Balanced 60–70 cannot starve a bursty Interactive Grok CLI while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Min-state 100. Parking 100. Boost Enabled. Cooling Active. Otherwise this soak is lying about Speed Shift.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input between bursts. Task Manager Performance does not sit in an efficiency-biased mid-range the entire soak while grok.exe is the foreground session.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with PERFEPP 60 is not forever.
  4. EPP still 0 on AC for every alias that exists. If someone set 50 to “save watts,” restore 0. If only PERFEPP is 0 and PERFEPP1 is still 60, that is not a pass on a hybrid package. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof Speed Shift is already performance-biased. Grok in-session schedulers expire in 7 days even when durable. Recreate them if missing. The Windows task is the host-forever pulse. Not systemd.

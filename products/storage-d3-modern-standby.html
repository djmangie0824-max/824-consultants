Storage D3 in Modern Standby vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the Turn off hard disk after page, and not the Network connectivity in Standby page. Sleep-vs-forever is whether S0ix paused the hourly. DISKIDLE is platter/STANDBY minutes while the session is still awake. Network-in-standby is the NIC during S0ix. NVMe APST is the drive dropping its own power states while the PCIe function is still D0. This page is the remaining storage PCI D-state during S0ix: Storport StorageD3InModernStandby can put inbox StorNVMe / StorAHCI into D3 (often D3cold) the moment the laptop enters Modern Standby.

The problem

The sleep-vs-forever pack already names S0 Low Power Idle as the standby that freezes Interactive-only tasks. The DISKIDLE pack already sets Turn off hard disk after to Never on AC so a SATA disk does not spin down while you are still “awake.” Both can be honest and the first Git object after a closed-lid hour still waits. Inbox StorNVMe / StorAHCI may still take the boot disk to PCI D3 when the platform enters Modern Standby. Resume is not a boot. RAM is still there. The disk is the thing that left.

grok.exe is alive. Task Scheduler still prints Ready and last result 267009 (still-running). Event Viewer shows stornvme or storahci Event 129 — Reset to device, \Device\RaidPort0. The operator buys another NVMe enclosure. The policy was Enable Storage Device D3.

Missing registry value is not Disabled. If StorageD3InModernStandby is absent, Storport checks ACPI _DSD StorageD3Enable, then a platform allowlist. Many S0ix laptops D3 the disk with no GUI row and no DWORD. This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd to paper over D3cold. Do not mint a Vercel slug because the first write after resume stalled. Do not kill Modern Standby with PlatformAoAcOverride on this page — that is a different layer.

What to change (plugged-in Grok desk)

  1. Confirm the standby layer is already named — powercfg /a lists Standby (S0 Low Power Idle). If S0ix is eating the hourly itself, that is still sleep-vs-forever. This page does not disable Modern Standby. It stops Storport from D3’ing the disk during it.
  2. Confirm DISKIDLE is already Never on AC if the row exists — if Turn off hard disk after is still 20 minutes, that is hard-disk-idle-timeout, not this page. PCIe ASPM Off and AHCI LPM Active on AC if those buses exist.
  3. Query before you write — Microsoft’s documented Storport key is HKLM\SYSTEM\CurrentControlSet\Control\Storage\StorageD3InModernStandby. DWORD 0 = Disable D3 support. DWORD 1 = Enable D3 support. There is usually no Power Options row. Windows Configuration Designer calls the same policy StorageD3InModernStandby / Enable Storage Device D3.
  4. Set 0 on this plugged-in desk — elevated. Then reboot so Storport reloads. On a travel cube that actually lives on battery, leaving 1 can be honest. A desk that never unplugs should not pretend it is a travel cube.
  5. Leave ACPI _DSD StorageD3Enable alone — that is firmware. The registry override is the operator click. Do not flash BIOS to “fix” a DWORD.
  6. Leave APST, DISKIDLE, and PlatformAoAcOverride alone on this click — APST is the NVMe controller while D0. DISKIDLE is minutes while awake. PlatformAoAcOverride kills S0ix itself. Wrong page for all three.
  7. Leave the Balanced (or current) plan in place — this page is one Storport DWORD, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /a
reg query HKLM\SYSTEM\CurrentControlSet\Control\Storage /v StorageD3InModernStandby
reg add HKLM\SYSTEM\CurrentControlSet\Control\Storage /v StorageD3InModernStandby /t REG_DWORD /d 0 /f

Reboot after the add. Query again. 0x0 is the pass. ERROR: The system was unable to find the specified registry key or value — before the add — means Storport is still allowed to follow _DSD / allowlist. That is not Disabled. After reboot, a still-missing key means the write did not stick; do not invent a second path under Control\Power. Inbox driver only: StorNVMe / StorAHCI. A third-party RAID/NVMe stack is a skip, not a registry paste under a vendor key you guessed.

How it splits from the other playbooks

  • Sleep vs forever — S0ix paused user tasks. Not the disk D-state inside that S0ix.
  • Network connectivity in Standby — NIC during S0ix. Not Storport D3.
  • Hard disk idle timeout — DISKIDLE minutes while awake. Not PCI D3 in Modern Standby.
  • NVMe APST — drive-autonomous NVMe power states while the PCIe function is still D0. Microsoft’s inbox StorNVMe path for Modern Standby is host-directed D3, not APST. Wrong click here.
  • PCI Express Link State Power Management — ASPM on the link while the device can still be D0. Not the D3 policy for storage in MS.
  • AHCI Link Power Management — HIPM/DIPM on the SATA PHY. Not D3cold of the storage function.
  • This page — AC StorageD3InModernStandby = 0 so Storport cannot D3 the boot disk during S0ix while the named task still looks Ready.

Soak test (what "passes" means)

  1. DISKIDLE already Never on AC if the row exists. ASPM / AHCI LPM already honest if those rows exist. Otherwise this soak is lying about the bus.
  2. StorageD3InModernStandby is 0 after reboot. Missing after the add is a fail of the write, not a skip.
  3. Short S0ix: lid closed or Sleep, cooling stand in place. Resume without a BitLocker recovery prompt caused by a vanished disk. Device Manager disk stays Present. No re-enumerate.
  4. First Git object / Grok session write after resume is not a multi-second stall. One silent Event 129 reset storm on stornvme/storahci is a fail if the DWORD was not 0.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a D3cold boot disk is not forever.
  6. Classic S3-only host = skip, not a red soak. Do not invent S0ix to make this page apply. Do not “fix” a stall by switching the whole plan to High performance. No fourth Grok TUI.

Pages 404 vs the public catalog

This property’s 404.html is an owner deny wall for unknown paths. That is correct for random URLs. It is not correct to treat a catalog SKU as vault just because github.io rendered that wall.

Incident this pack was written from

Live catalog on github.io was healthy. Local clone was one commit ahead with Git + Node, sleep-vs-forever, and USB Ethernet pages. Fetching those URLs returned Private property / DENY BY DEFAULT — the custom 404.html, not a vault dump and not proof Law 237 wants the catalog gutted.

Raw GitHub for the same path was a true 404. Origin SHA lagged the laptop. GitHub MCP was absent this session; fail-fast git push had no stored username. The heal is land the files on main, not convert products/index.html into a deny wall.

What not to do

  • Do not “protect the vault” by Disallow-all robots or emptying the sitemap.
  • Do not SHA-bump home with PLACEHOLDER or essay-chrome.
  • Do not turn 404.html into a public catalog. Unknown paths stay denied.
  • Do not publish IBKR numbers while explaining a 404.

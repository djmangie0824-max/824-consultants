Processor idle time check vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Processor idle disable page, not idle promote / demote thresholds, not idle state maximum, and not idle threshold scaling. Disable is the allow/deny. Promote/demote are percent hysteresis. State maximum is a depth cap. Scaling is whether the engine rescales that pair. This page is the sample window: Power Options → Processor power management → Processor idle time check. Alias IDLECHECK. GUID c4581c31-89ab-4597-8e2b-9c9cab440e6b. Units are microseconds, not percent, not a C-state index.

The problem

On this Yoga the measured idle-disable row is still Enable idle (index 0) on AC and DC. That is honest heat: Disable idle keeps the package in C0. Enable idle remains. The promote/demote pair is still Balanced 60% / 40% until that sibling pack runs. The idle engine still has to sample idle residency over a window before it can promote or demote. That window is IDLECHECK. This host printed 0x0000c350 = 50000 µs = 50 ms on AC and DC. Scheme SCHEME_BALANCED 381b4222-f694-41f0-9685-ff5bb260df2e.

An Interactive Grok CLI is bursty: a paint, a wait, a JSON tool, a wait. A tool call that is shorter than the sample window still looks idle. The engine does not demote out of C6 until the next check. grok.exe is alive. Task Scheduler still prints Ready and last result 267009. The first token after a quiet gap pays a C-state wake that a 50 ms window did not see in time. Raising promote to 100 does not shrink the window. Disabling idle does not shrink the window — it deletes C-states and adds heat. This page is the microseconds.

Do not install systemd to paper over a 50 ms sample. Do not mint a Vercel slug because the TUI paused after a quiet minute. Do not cargo-cult IDLECHECK 1 (one microsecond, the legal minimum) as a forever loop — that is max evaluation rate, not a soak. Do not confuse this row with JavaScript timer frequency or multimedia timer resolution. Those are timer coalescing. This is the processor idle engine’s own check interval.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here.
  2. Confirm IDLEDISABLE is still Enable idle (0) — if it is already Disable idle (1), this window is unused. Heat was the other pack. Do not shrink a window the engine is no longer sampling.
  3. Query IDLECHECK with /qh before you write — powercfg /query omits ATTRIB_HIDE rows. This host printed 50000 µs. If /qh omits the GUID, this edition did not expose the knob. Stop. Do not invent a registry paste. Do not guess GUID c4581c31-89ab-4597-8e2b-9c9cab440e6b from a forum as a fleet trick.
  4. Set Plugged in to 10000 microseconds — that is 10 ms. Index 10000 decimal. On battery stays 50000 if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  5. Do not start at 1 µs — legal minimum is 1. That is max evaluation rate. Watts and scheduler noise go up. 10 ms is the pass for this desk. 50 ms on AC is a fail once the percent pair is already honest. 200 ms is slower than Balanced.
  6. Leave promote, demote, state maximum, and scaling as siblings — this click does not write 100/80. This click does not cap C-state depth. This click does not Disable scaling. Those are other pages.
  7. Activate the current scheme after the AC index write — /setacvalueindex does not apply until /setactive SCHEME_CURRENT. Query again. AC 0x00002710 = 10000 is the pass. 0x0000c350 is still 50 ms — a fail for this desk.
  8. Leave the Balanced (or current) plan in place — one processor knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO. Do not paste live brokerage numbers next to that output. Do not paste auth.json.

How it splits from the other playbooks

  • Processor idle disable — allow/deny. Enable idle vs stay C0. Heat. This page assumes Enable idle is still the honest choice.
  • Idle promote / demote thresholds — percent hysteresis 60/40 → 100/80. How idle the window must be. Not how long the window is.
  • Processor idle state maximum — depth cap. 0 = unlimited. Not a sample rate.
  • Processor idle threshold scaling — Disable vs Enable scaling. Not microseconds.
  • JavaScript timer frequency / multimedia timer resolution — timer coalescing. Wrong subsystem.
  • Hard disk idle timeout — DISKIDLE. Spindle, not CPU.
  • This page — AC IDLECHECK 10000 µs so a 50 ms Balanced window cannot miss a Grok tool burst while Enable idle is still on.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Enable idle still 0 if that is the heat choice. Promote/demote already named if that pack ran. Stand in the path.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. Fire a 5-minute named task. The first token after the quiet gap is not a hitch that a 50 ms window would have classified as still-idle.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with IDLECHECK 50000 is not proof the window is already 10 ms.
  4. IDLECHECK still 10000 on AC. If someone set 200000 µs to “save watts,” restore 10000 on AC. Do not “fix” it by switching the whole plan to High performance. Do not write 1 µs as a cargo-cult.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof the sample window is honest. Grok in-session schedulers expire in 7 days even when durable. Isolation-empty scheduler_list is skip recreate, not missing-forever. The Windows task is the host-forever pulse. Not systemd.

The problem

The sibling processor knobs can already be honest on AC. Frequency floor 100. Ceiling 100. Turbo allowed. Cores unparked. Idle policy named. EPP already 0. Hybrid class already Prefer performant. The TUI still starves on the first token after a quiet stretch. Windows still waits for a remaining percent busy before it will increase a P-state. That row is PERFINCTHRESHOLD. Typical Balanced AC is 60. Typical Balanced DC is 90. An Interactive Grok CLI is bursty: a paint, a wait, a JSON tool, a wait. Utilization between bursts is 5–30, not 60. The OS governor does not step up. Clocks stay where the last decrease left them. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died and opens a fourth TUI. The increase threshold was 60.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. Min-state 100 of a P-state the governor will not enter is still a slow desk. Boost Enabled only permits turbo P-states. EPP 0 is a 0–100 hardware hint, not a percent-busy gate. Autonomous mode (PERFAUTONOMOUS) can already be Enabled on this host — that is Speed Shift picking P-states, not a skip of this click. When HWP is later Disabled, or when the package still reads the OS threshold, 60% is the liar. Do not install systemd to paper over a 60% gate. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide eight other forever-loop bugs.

How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). This page is the remaining percent busy that must be crossed before the OS steps up from that floor (PERFINCTHRESHOLD).
  • Maximum processor state — frequency ceiling (PROCTHROTTLEMAX). A 100 ceiling with a 60% increase gate still waits.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Enabled turbo with a 60% gate still refuses the step-up.
  • Core parking — unparked-core floor (CPMINCORES). Parking is not remaining-busy.
  • Processor idle disable — C-states (IDLEDISABLE). Wake from C6 is not a P-state increase.
  • Processor power throttling — the catalog ceiling / EcoQoS overlay page. Not this utilization gate.
  • Intel Speed Shift / EPP — HWP bias 0–100 (PERFEPP). Not a percent of busy. Autonomous Enabled does not replace this click and this click does not write EPP.
  • Heterogeneous thread scheduling — P vs E class pick (SCHEDPOLICY). Not remaining-busy.
  • This page — AC Processor performance increase threshold = 10% so Balanced 60% remaining-busy cannot stall an Interactive Grok CLI while the named task still looks Ready.

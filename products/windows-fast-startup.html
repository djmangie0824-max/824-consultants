Windows Fast Startup vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the lid-close page, and not the USB selective suspend page. Sleep-vs-forever is S0ix while the lid is already shut. Lid-close is the action Windows takes when the lid moves. USB suspend sleeps the NIC. This page is hybrid shutdown: Start menu Shut down with Fast Startup still on, so the next power button is not a boot the Interactive-only tasks can see.

The problem

LEXXII-Materialize-Forever is Interactive-only. That is honest for a Grok TUI that must not stack a fourth window. Fast Startup (Hiberboot) then lies about Shutdown. Windows closes the user session, hibernates the kernel, and on the next power button restores that kernel without a full logon. Task Scheduler shows Ready. Next-run is in the future. No hourly fire happens until someone actually signs in.

The operator thinks the host-forever layer survived a shutdown. It survived a hibernated kernel. Grok in-session schedulers are already a 7-day layer. Fast Startup makes the Windows layer look armed while it is waiting for a logon that a hybrid boot did not complete.

Shutdown vs hybrid shutdown

What you clickedWhat happens to the forever loop
Sleep / Modern StandbyDifferent layer. See sleep-vs-forever.
Lid closeDifferent layer. See lid-close Do nothing.
RestartReal boot. Interactive-only tasks wait for logon, then fire. Expected.
Shut down with Fast Startup ONHybrid shutdown. Kernel hibernated. Next power looks like a boot. User-context tasks stay quiet until a real logon.
Shut down with Fast Startup OFFActual shutdown. Next power is a cold boot. Same logon wait, but the event log does not lie about hibernate.
Hibernate (explicit)Session written. Worse than Fast Startup for an hourly loop. Leave it available only if a UPS drain policy needs it.
Do not powercfg /hibernate off as the first click. That kills Fast Startup and Hibernate. A UPS-backed Grok desk may still want Hibernate. Uncheck Fast Startup. Leave the hibernate file unless you measured that you do not need it.

What to change (this Windows profile)

  1. Control Panel → Hardware and Sound → Power Options → Choose what the power buttons do — click Change settings that are currently unavailable.
  2. Shutdown settings — uncheck Turn on fast startup (recommended). The word “recommended” is for laptop resume, not for Interactive-only Task Scheduler.
  3. Leave Hibernate available unless this host has no UPS drain path and you want the disk back. Fast Startup is the hybrid-shutdown checkbox, not the Hibernate checkbox.
  4. Confirm, then soak — registry value HiberbootEnabled must be 0 after the click. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /a
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power" /v HiberbootEnabled

powercfg /a lists sleep states this firmware actually offers. If Fast Startup is still named there after the checkbox, the setting did not stick (needs the unavailable-settings unlock, or a policy we do not run). Registry 0x0 is off. 0x1 is still on.

Soak test (what "passes" means)

  1. Note LEXXII-Materialize-Forever last-run and next-run.
  2. Start menu → Shut down. Wait two minutes. Power on. Sign in.
  3. Event Viewer → Windows Logs → System. A hybrid-boot / Hiberboot path after that click is a fail on this page.
  4. Task Scheduler last-run must not claim an hourly fire during the “off” window. If it silently skipped until logon and the event log shows hybrid shutdown, Fast Startup was the layer.
  5. Repeat after the checkbox is off. The next Shut down must be a real shutdown in the log. Then this layer is done — remaining silence is Standby, lid, USB, or a missing task.

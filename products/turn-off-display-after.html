Turn off display after vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the sleep vs forever page, not the lid close page, and not a DisplayPort cable review. Sleep after is the session. Lid is the chassis. The cable is hardware. This page is the remaining panel timer: Power Options → Display → Turn off display after. Ten minutes on AC still blacks dual ultrawide. The dock re-enumerates. Task Scheduler still shows Ready.

Download markdown Sleep vs forever first Lid close

The problem

The sleep-vs-forever pack already tells you plugged-in sleep is not 5–20 minutes. Lid close is Do nothing on AC. That work can be done and a ship still stalls on video. Balanced Turn off display after on AC is often 5 or 10 minutes. The panels go black. DP/HDMI drop. The dock treats it as unplug. Windows rebuilds the desktop. The Grok TUI is still a process. The named task still prints Ready and last result 267009 (still-running). The operator thinks the DP lead failed. A timer napped the link.

This is not Sleep. This is not HIPM. powercfg /a still reports the same standby type. Requests can still be None. The display idle policy is the liar. Do not install systemd to paper over 10 minutes. Do not mint a Vercel slug because a panel slept. Do not buy another DP cable until this row is Never on AC.

What to change (plugged-in Grok desk)

  1. Confirm the session layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever. If the desk still intends to sleep every idle, stop here.
  2. Power Options → Change plan settings → Change advanced power settings → Display → Turn off display after — set Plugged in to 0 minutes (Never). On battery may stay 5–10 if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  3. Leave Sleep after and Hard disk idle alone on this click — those are siblings. Do not treat a parked platter as this row.
  4. Leave the Balanced (or current) plan in place — this page is one display knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  5. Confirm, then soak — query VIDEOIDLE. 0 on AC is the pass. If the alias is missing, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_VIDEO VIDEOIDLE
powercfg /a

SUB_VIDEO / VIDEOIDLE is the display idle-timeout row (seconds in the query; the GUI speaks minutes). 0 on AC is Never for this desk. A remaining AC value of 300 or 600 is 5 or 10 minutes — Balanced default, not a pass. Sleep after is STANDBYIDLE, not this click. Disk idle is DISKIDLE, not this click. If powercfg omits VIDEOIDLE, this edition did not expose the knob — stop; do not invent a registry hack on a public page.

How it splits from the other playbooks

  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not panel timer.
  • Lid close Do nothing — lid action. Not Display minutes.
  • powercfg /requests — a named holder pinning DISPLAY. Not VIDEOIDLE.
  • DisplayPort cable sit/stand — slack and latch. Not a timer.
  • Hard disk idle timeout — platters, not panels. Sibling, not this click.
  • Console lock display off — lock-screen panel timer. Not unlocked VIDEOIDLE.
  • This page — AC Turn off display after = 0 so idle minutes cannot drop dual ultrawide while the named task still looks Ready.

Soak test (what "passes" means)

  1. Sleep and lid already honest. Otherwise this soak is lying about the session.
  2. Leave the desk idle 30 minutes, lid closed, dedicated NIC plugged, dual ultrawide up. Panels stay on. Display settings still show both screens. A black-then-handshake on first input is a fail if VIDEOIDLE was not 0 on AC.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a dead DP link is not forever.
  4. VIDEOIDLE still 0 on AC. If someone set 10 minutes to “save the OLEDs,” restore 0 on this class of operator desk. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof the panels stayed enumerated.

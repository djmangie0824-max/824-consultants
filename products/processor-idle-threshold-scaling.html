Processor idle threshold scaling vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the idle promote / demote thresholds page, not Processor idle disable, not idle time check, and not idle state maximum. Promote/demote are the percent pair. This page is whether the idle engine is allowed to rescale that pair: Power Options → Processor power management → Processor idle threshold scaling. Alias IDLESCALING. GUID 6c2993b0-8f48-481f-bcc6-00dd2742aa06. Values are Disable scaling (0) and Enable scaling (1). This host printed Disable scaling on AC and DC.

The problem

The promote/demote pack names a hysteresis pair. Balanced default on this Yoga is 60% / 40%. The forever-desk click on that page is 100 / 80 on AC. Those numbers only stay those numbers if the engine is not allowed to rescale them. IDLESCALING Enable scaling (1) lets the idle engine move the thresholds with conditions. A soak that printed 100 / 80 can walk back toward a 60 / 40 feel without anyone reopening Power Options. grok.exe is alive. Task Scheduler still prints Ready and last result 267009. The operator thinks the percent pack failed. Scaling was Enabled.

This host already has Disable scaling (0). That is the pass. This page still ships because Enable scaling is a one-click undo of the percent pack, and because other images default differently. The click here is: query, keep 0, restore 0 if someone Enabled it to “save watts.” Do not Enable scaling on AC as a forever-loop upgrade. There is no upgrade. 0 is the hold.

Do not install systemd to paper over a rescaled pair. Do not mint a Vercel slug because 100/80 drifted. Do not Disable idle on this click. Do not rewrite 100/80 on this page — that is the sibling.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. If the desk still intends to sleep every idle, stop here.
  2. Confirm IDLEDISABLE is still Enable idle (0) — if it is already Disable idle (1), scaling is unused.
  3. Query IDLESCALING with /qh before you write — this host printed 0 Disable scaling. If /qh omits the GUID, this edition did not expose the knob. Stop. Do not invent a registry paste. Do not guess GUID 6c2993b0-8f48-481f-bcc6-00dd2742aa06 from a forum as a fleet trick.
  4. If AC is 1, set Plugged in to Disable scaling (0) — if AC is already 0, do not write 1. On battery stays Disable scaling if this laptop actually travels.
  5. Do not Enable scaling to “help” 100/80 — Enable scaling is the undo. The percent pack writes the pair. This pack holds it.
  6. Leave promote, demote, time check, and state maximum as siblings — this click does not write 100/80. This click does not write 10000 µs. This click does not cap depth.
  7. Activate the current scheme after any AC index write — /setacvalueindex does not apply until /setactive SCHEME_CURRENT. Query again. AC 0x00000000 is the pass. 0x00000001 is Enable scaling — a fail for this desk.
  8. Leave the Balanced (or current) plan in place — one processor knob. Do not paste live brokerage numbers. Do not paste auth.json.
powercfg /qh SCHEME_CURRENT SUB_PROCESSOR IDLESCALING
powercfg /setacvalueindex SCHEME_CURRENT SUB_PROCESSOR IDLESCALING 0
powercfg /setactive SCHEME_CURRENT
powercfg /qh SCHEME_CURRENT SUB_PROCESSOR IDLESCALING

SUB_PROCESSOR is the processor subgroup. IDLESCALING is Processor idle threshold scaling. 0 = Disable scaling (this host now, the pass). 1 = Enable scaling (the undo). Run the /qh line first. If the alias is omitted, skip the /setacvalueindex line. If AC is already 0, the set line is a no-op hold, not a restamp of the percent pair.

How it splits from the other playbooks

  • Idle promote / demote thresholds — the percent values. 60/40 vs 100/80. This page does not write those numbers.
  • Processor idle disable — allow/deny. Heat. Not a rescale.
  • Processor idle time check — sample window in microseconds. Not a rescale.
  • Processor idle state maximum — depth cap. Not a rescale.
  • This page — AC IDLESCALING Disable scaling (0) so a named promote/demote walk cannot undo itself.

Soak test (what "passes" means)

  1. Timeouts already honest. Enable idle still 0 if that is the heat choice. Promote/demote already named if that pack ran.
  2. Query IDLESCALING after 30 minutes idle. Still 0 on AC. A 100/80 pair (if written) still reads 100/80, not a drifted 60/40.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with scaling 0 is the hold, not a skip of the percent pack.
  4. If someone set Enable scaling to “save watts,” restore Disable scaling on AC. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Isolation-empty scheduler_list is skip recreate. The Windows task is the host-forever pulse. Not systemd.

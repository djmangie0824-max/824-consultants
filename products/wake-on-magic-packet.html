Wake on Magic Packet vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Allow wake timers page and not the powercfg /lastwake page. Those packs are Windows RTC / important-only timers and the log of who yanked the last sleep. This page is the NIC property: Device Manager → the dedicated Ethernet adapter → Power Management “Allow this device to wake the computer” plus Advanced Wake on Magic Packet and Wake on pattern match. A directed LAN packet can yank Modern Standby or S3 at 03:00 after sleep, lid, USB suspend, ASPM, and EEE are already honest. The named task still looks Ready. That wake is not proof LEXXII-Materialize-Forever fired.

The problem

A docked closed-lid Grok desk wants the Interactive session to stay up, or to stay honestly asleep until the next scheduled run — not to bounce because a printer, NAS, or leftover WoL tool sent FF:FF:FF:FF:FF:FF plus the MAC. OEM defaults often leave Magic Packet On. Pattern match is broader and will wake on more than a classic WoL frame. Task Scheduler WakeToRun can already be checked. Allow wake timers can already be Enable. Those settings do not own a magic packet. The NIC does.

Turning the whole USB Ethernet device off is the wrong fix. The dedicated NIC is the ship path when Wi-Fi power-save lies. This page is two Advanced properties and the Power Management wake checkbox on that NIC, after USB selective suspend and EEE are already honest. Do not disable the adapter. Do not install systemd. Do not mint a Vercel slug because the laptop woke at 03:00.

What to change (plugged-in Grok desk)

  1. Confirm the timer layer is already honest — Sleep / lid / Allow wake timers already done. If lastwake names the Windows timer, stop here and use those packs.
  2. List who may wake the box — run the commands below. The dedicated USB Ethernet or dock NIC showing in wake_armed is expected when the Power Management wake checkbox is on.
  3. Device Manager → Network adapters → the dedicated NIC → Power Management — if this desk is not using directed wake, uncheck Allow this device to wake the computer. Leave the adapter enabled. Leave “Allow the computer to turn off this device to save power” to the USB-suspend pack, not this click.
  4. Same NIC → Advanced — set Wake on Magic Packet to Disabled. Set Wake on pattern match to Disabled if the property exists. Exact labels vary by Realtek / Intel / dock firmware. Missing property after a driver install is a skip, not a registry hack.
  5. Leave EEE, Speed & Duplex, and USB selective suspend alone on this click — those are the other playbooks. Magic Packet Off is not EEE Off.
  6. Confirm — wake_armed no longer lists that NIC, or lastwake after a soak is not a magic packet the operator did not send.
powercfg /devicequery wake_armed
powercfg /devicequery wake_programmable
powercfg /lastwake
powercfg /waketimers

wake_armed is the live list. wake_programmable is who could be armed. /lastwake names the previous yank. /waketimers is the Windows timer list — different layer. Apply Device Manager changes before the soak; a remaining armed NIC is not a pass. If the Advanced tab omits Magic Packet, this driver did not expose the knob — stop; do not invent a registry WoL DWORD on a public page.

How it splits from the other playbooks

  • Allow wake timers — Windows RTC / important-only. Not a NIC frame.
  • powercfg /lastwake — the log. This page is the NIC click the log pointed at.
  • Energy Efficient Ethernet — idle downshift, not a wake packet.
  • USB selective suspend — the NIC napped. This page is the NIC waking the PC.
  • Unattended sleep timeout — sleep after a wake. Not the wake source.
  • This page — Magic Packet / pattern match Off on a docked AC desk that is not using directed wake.

Soak test

  1. Sleep, lid, USB suspend, ASPM, EEE, and Allow wake timers already honest. Otherwise this soak is lying about a different layer.
  2. Lid closed, dedicated NIC plugged, named task next-run still in the future. Leave the LAN idle. No 03:00 surprise S0 from a packet the operator did not send.
  3. powercfg /lastwake after a scheduled task run names the timer or the operator, not a magic packet.
  4. The USB Ethernet adapter is still Enabled and still has a link. Disabling the NIC fails this soak even if WoL is off.
  5. Host-forever is still LEXXII-Materialize-Forever. Grok in-session schedulers still expire in 7 days. Not systemd.

What this page is not

  • Not a ban on intentional Wake-on-LAN. If the operator uses directed wake, skip.
  • Not “disable the NIC.” The dedicated Ethernet review still stands.
  • Not Allow wake timers. Not lastwake. Not EEE. Not USB selective suspend.
  • Not a Linux FULL AUTO daemon on this Windows profile.
  • Not a brokerage number. Live capital stays off Pages.

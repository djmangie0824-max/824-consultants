Lid close Do nothing vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the USB selective suspend page, and not the cooling-stand review. Sleep-vs-forever explains why a Ready task looks dead. Selective suspend sleeps the NIC. The cooling stand is the air under a closed lid. This page is the lid action: what Windows does the moment the operator closes the laptop on a plugged-in Grok desk.

Download markdown Sleep vs forever Cooling stand (hardware)

The problem

The operator architecture on this class of Windows Grok host is closed-lid on a cooling stand, docked, Ethernet dedicated, Task Scheduler Interactive-only. The default lid action is Sleep. Closing the lid then pauses user tasks even when the machine “looks on.” LEXXII-Materialize-Forever misses the hour. Grok in-session schedulers are already a 7-day layer. A sleeping lid makes the Windows host-forever layer fake-dead too.

Hibernate is worse: the session is gone. Shut down is a hard stop. Sleep on battery can stay Sleep — this desk is not a travel cube pretending to be a server. Plugged-in must be Do nothing or the named tasks never see the closed-lid interval they were built for.

Lid actions (what each one actually does)

Plugged-in lid actionWhat happens to the forever loop
SleepUser tasks pause. Interactive-only Task Scheduler does not fire. The host may still show a LED.
HibernateSession written and powered off. Worse than Sleep for an hourly loop.
Shut downHard stop. No loop.
Do nothingLid is a thermal lid, not a power button. Tasks can still fire if Modern Standby and USB suspend are also healed.
Do nothing is necessary and not sufficient. Connected standby can still freeze Task Scheduler with the lid already set to Do nothing — that remaining layer is sleep-vs-forever. A dead NIC under a closed lid is USB selective suspend. Do not cargo-cult all three into one click.

What to change (plugged-in Grok desk)

  1. Control Panel → Hardware and Sound → Power Options → Choose what closing the lid does — set When I close the lid / Plugged in to Do nothing. On battery may stay Sleep if this laptop actually leaves the desk.
  2. Same screen: When I press the power button — leave that as Shut down or Sleep. Do nothing on the lid is not a license to make the power button a no-op.
  3. Confirm with powercfg (AC only) — lid action index 0 is Do nothing, 1 Sleep, 2 Hibernate, 3 Shut down.
  4. Do not change the lid action via a fleet GPO we do not run. This is one Windows profile. Agents do not invent a domain.
powercfg /query SCHEME_CURRENT SUB_BUTTONS LIDACTION
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
powercfg /setactive SCHEME_CURRENT

Read the AC index before writing it. If AC already shows 0x00000000, the lid layer is set — remaining closed-lid death is Standby or USB, not this page. Do not paste live brokerage numbers next to that output. Do not paste auth.json.

Soak test (what "passes" means)

  1. Plugged in. Close the lid on the cooling stand for ten minutes. The machine must not enter Sleep/Hibernate from the lid. A black-then-resume cycle is a fail on this page.
  2. With the lid still closed, query LEXXII-Materialize-Forever. Next-run must still be in the future. A Ready task that never fires while the lid is shut failed the layer this page owns.
  3. Open the lid. No “resuming” splash. If Windows is waking from Sleep, the AC lid action is not Do nothing.

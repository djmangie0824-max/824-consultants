Thunderbolt/USB4 Runtime D3 vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the PCI Express ASPM page, not the USB 3 Link Power Management page, and not the USB selective suspend page. ASPM parks the PCIe link while the device stays in D0. USB 3 LPM is SuperSpeed U1/U2. Selective suspend is USB-stack U3 on a hub or NIC. This page is the remaining controller: Device Manager → USB4 Host Router / Intel Thunderbolt controller → Power Management → Allow the computer to turn off this device to save power. That checkbox is Runtime D3. The controller itself goes D3Cold while the laptop is still in S0. The dock full re-enumerates. Task Scheduler still shows Ready.

The problem

The USB selective suspend, USB 3 LPM, and PCI Express ASPM packs can already be honest on AC. USB suspend Disabled. USB 3 LPM Off. Link State Power Management Off. The dock still dies after idle. Displays black, then come back as if the cable was yanked. The dedicated NIC on the dock re-enumerates. Device Manager flashes. Event Viewer shows Kernel-PnP surprise removal. LEXXII-Materialize-Forever still claims Ready and last result 267009 (still-running). The operator thinks Git or the dock SKU failed. The Thunderbolt controller left.

Runtime D3 (RTD3) is not ASPM. ASPM is L0s/L1 on a live D0 device — quieter, no controller disappearance. RTD3 is the device entering D3Hot or D3Cold while the platform stays in S0. A USB4 Host Router or Intel Thunderbolt controller that takes D3Cold powers off the whole Thunderbolt domain: tunneled DisplayPort, tunneled PCIe, tunneled USB. Wake needs a PME / in-band hotplug. That is a full re-enumerate, not a SuperSpeed U2 blink.

This happens while the machine is awake. It is not Modern Standby. It is not USB Root Hub selective suspend. It is not a High-performance plan essay. Do not install systemd to paper over a D3Cold controller. Do not mint a Vercel slug because the dock blinked. Do not buy a second dock until the controller is honest.

What to change (plugged-in Grok desk)

  1. Confirm the three bus layers are already done — USB selective suspend Plugged in = Disabled. USB 3 Link Power Management on AC = Off if the row exists. PCI Express Link State Power Management on AC = Off if the row exists. See USB suspend, USB 3 LPM, and ASPM. If those are still travel defaults, stop here.
  2. Device Manager → View → Devices by connection — find USB4 Host Router (Microsoft USB4 stack) and/or Intel(R) Thunderbolt(TM) Controller. They hang off a PCI Express Root Port. If both names exist, they are two nodes. If neither exists, skip this page.
  3. Properties → Power Management — uncheck Allow the computer to turn off this device to save power on the Host Router and on the Thunderbolt controller. That is the AC pass for this desk. Do not disable the device. Do not uninstall usb4.sys. Do not uninstall the Intel Thunderbolt driver.
  4. Leave the PCI Express Root Port checkbox alone — unchecking the parent root port is a cargo-cult that can D3 other devices on that port. This page is the Thunderbolt/USB4 node only.
  5. Intel Thunderbolt Control Center, if it is already installed — disable Runtime D3 / RTD3 if that settings row exists. If Control Center is not installed, skip. Do not download a random Intel utility from a forum to create the row.
  6. BIOS TBT RTD3 only if the Device Manager checkbox is missing or does not stick across reboot — firmware names vary: Thunderbolt Runtime D3, TBT RTD3, USB4 Runtime D3. Set Disabled on a desk that never unplugs. Do not flash Thunderbolt firmware from this page. Do not hunt a SUB_THUNDERBOLT powercfg alias — this host class does not have one.
  7. Leave the Balanced (or current) plan in place — this page is one Device Manager checkbox, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  8. Confirm, then soak — the controller still shows Status OK. The checkbox stays off. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
Get-PnpDevice | Where-Object { $_.FriendlyName -match 'Thunderbolt|USB4 Host Router' } | Format-Table Status, Class, FriendlyName
powercfg /query SCHEME_CURRENT SUB_PCIEXPRESS
powercfg /query SCHEME_CURRENT SUB_USB

Get-PnpDevice names the controller. Status OK is not proof the Power Management checkbox is off — open the property sheet. SUB_PCIEXPRESS is ASPM. SUB_USB is USB selective suspend and USB 3 LPM. Those queries prove the earlier layers, not this click. There is no portable SUB_THUNDERBOLT alias on this host class. If Device Manager omits USB4 and Thunderbolt, stop. Do not invent a registry paste on a public page. Hidden firmware is not a GUID from a forum.

How it splits from the other playbooks

  • USB selective suspend — USB-stack U3 / hub Power Management. The USB Root Hub, not the USB4 Host Router.
  • USB 3 Link Power Management — SuperSpeed U1/U2 on a USB NIC or USB-C hub. The Thunderbolt controller stays Present.
  • PCI Express Link State Power Management — ASPM L0s/L1. Device stays D0. Link naps. Controller stays in Device Manager.
  • Energy Efficient Ethernet — IEEE 802.3az on the adapter PHY. The NIC stays Present.
  • Dock multi-monitor review — hardware criteria, SKU pending. Not a Power Management checkbox.
  • This page — Runtime D3 so the USB4 Host Router / Thunderbolt controller cannot D3Cold the dock while the named task still looks Ready.

Soak test (what "passes" means)

  1. USB selective suspend already Disabled on AC. USB 3 LPM already Off on AC if the row exists. PCI Express ASPM already Off on AC if the row exists. Lid close already Do nothing on AC. Otherwise this soak is lying about the bus.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, Thunderbolt/USB4 dock + dedicated NIC plugged. The USB4 Host Router / Thunderbolt controller stays Present. One silent controller disappearance is a fail on this page.
  3. Displays stay, or resume without a “monitor identified” reconnect storm. One full dock re-enumerate is a fail — but if the controller never left Device Manager, it is ASPM or USB, not this one.
  4. Dock NIC stays Present. A NIC that vanishes with the controller is this page. A NIC that flaps while the controller stays OK is USB 3 LPM or USB suspend.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a D3Cold Thunderbolt domain is not forever.
  6. The Power Management checkbox still unchecked. If firmware re-checked it after reboot, that is the BIOS TBT RTD3 step, not a High-performance plan switch.
  7. Missing USB4 and Thunderbolt names = skip, not a red soak. Do not invent the checkbox in the registry.
  8. No fourth Grok TUI. Last result 267009 is still-running, not proof the dock stayed up.

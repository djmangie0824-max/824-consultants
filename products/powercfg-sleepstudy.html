powercfg /sleepstudy vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the CSEnabled skip page, not the /lastwake forensic, and not /requests. Sleep-vs-forever tells you S0ix can freeze Interactive-only tasks while the lid looks on. CSEnabled on this Yoga 7 class is skip the DWORD — S3 is not offered. /lastwake names who yanked the last sleep. /requests names who is pinning DISPLAY or SYSTEM while awake. This page is the remaining Modern Standby HTML report: powercfg /sleepstudy. It lists Connected Standby sessions, DRIPS residency, and remaining consumers. The report stays on disk. It does not go on GitHub Pages.

The problem

LEXXII-Materialize-Forever is Interactive-only. Lid can already be Do nothing on AC. Sleep after can already be Never. Wake timers can already be Enable. Task Scheduler still prints Ready. Last result 267009 is still-running. The closed-lid docked hour still missed. The operator blames Grok. The box may have entered Standby (S0 Low Power Idle) — Connected Standby / Modern Standby — and frozen the user session while RAM stayed powered. Sleep-vs-forever already named that failure mode. It did not produce the session list.

powercfg /sleepstudy is the evidence. It is not a Power Options click. It is not a registry cut. It writes an HTML report of CS sessions this firmware actually entered: start, duration, percent of time in DRIPS (Deepest Runtime Idle Platform State), and the remaining activators that blocked DRIPS — NIC, USB hub, radios, display, an OEM PEP. A missed hourly that lines up with a CS session is S0ix, not a dead Grok scheduler. A missed hourly with no CS session in that window is a different layer. Poor DRIPS with a named remaining consumer is the sibling that owns that name, not a fourth TUI.

On this class of laptop, CSEnabled already says skip: powercfg /a lists S0 Low Power Idle and does not list S3. Writing CsEnabled=0 does not invent S3. Sleep study is how you prove residency without that cargo-cult DWORD. This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd because DRIPS printed 12%. Do not paste the report next to live NLV. NLV stays off Pages. Device instance paths and adapter names in that HTML are local forensics, not public property.

What to run (plugged-in Grok desk)

  1. Confirm this firmware is AoAc — elevated powercfg /a must list Standby (S0 Low Power Idle). If it only lists S3, this pack does not apply. If it lists S0 and not S3, you are on the Yoga 7 class path: CSEnabled skip, sleep study for evidence. See CSEnabled.
  2. Confirm the timeout layer is already done — plugged-in Sleep after is not 5–20 minutes. Lid close on AC is Do nothing if that is the desk policy. Otherwise the report is a mix of intended sleep and a missed hourly. See sleep-vs-forever.
  3. Generate the report locally — elevated Command Prompt: powercfg /sleepstudy /duration 1. Default without /duration is three days of CS history. Write it somewhere you own: powercfg /sleepstudy /duration 1 /output %USERPROFILE%\sleepstudy-report.html. Open the HTML in a browser on this host. Do not commit it. Do not drag it onto Pages.
  4. Classify the missed hour — a CS session whose start/duration covers the frozen hourly is S0ix residency. No CS session in that window means CS is not the liar; go back to /requests, Hibernate, or /lastwake. A session with poor DRIPS lists remaining consumers — NIC, USB, radios. Name them. Then go to the sibling that owns that name: network in standby, USB root hub, Wi-Fi power saving, Bluetooth.
  5. Act. Do not cargo-cult — remaining consumer that is the dedicated NIC: NIC-in-standby policy, not a fourth Grok window. Remaining consumer that is a HID bump: expected on a docked desk. Do not unplug the mouse to “heal” DRIPS. Do not invent CsEnabled=0 on firmware that does not offer S3. Soak. Do not paste auth.json next to that HTML.
powercfg /a
powercfg /sleepstudy /duration 1 /output %USERPROFILE%\sleepstudy-report.html
schtasks /Query /TN "LEXXII-Materialize-Forever" /FO LIST /V

/a is the capability list. Sleep study is the session list. They are not the same object. /duration 1 is one day of history — enough for a closed-lid soak, less noise than the three-day default. /xml exists; do not publish that either. powercfg /energy is a different 60-second trace. powercfg /batteryreport is battery history. powercfg /systemsleepdiagnostics is classic S3. None of those replace sleep study on an AoAc desk. Device paths and radio names stay in the local HTML.

How it splits from the other playbooks

  • Sleep vs forever — the diagnosis that S0ix / Interactive-only / 267009 can fake a dead loop. This page is the CS session evidence.
  • CSEnabled — the firmware/policy knob. On this class, skip. Sleep study does not change that skip.
  • /lastwake — who yanked the last sleep. One wake. Not a CS residency table.
  • /requests — holders while the session is already awake. Sleep study is what happened inside CS.
  • Network in Standby — NIC policy during CS. Sleep study may name that NIC as a remaining consumer.
  • powercfg /energy — 60-second energy-efficiency HTML. Timer resolution, USB errors. Not CS sessions. Do not publish it either.
  • This page — run /sleepstudy, classify the missed hour against CS sessions, keep the HTML local.

Soak test (what "passes" means)

  1. powercfg /a already lists S0 Low Power Idle. Sleep after and lid policy already match the desk. Otherwise this soak is lying about which state ran.
  2. Plugged in. Lid closed on the dock for sixty minutes. Generate /sleepstudy /duration 1 after the hour.
  3. If the named task last-run advanced across that hour, CS either did not fire or did not freeze Interactive — pass for this layer. Classify any CS session anyway so the next miss has a baseline.
  4. If last-run froze and sleep study shows a CS session covering that hour, this layer is the liar. Do not spawn a fourth Grok TUI. Do not write CSEnabled on this class. Change lid / Sleep after if the desk must stay Interactive.
  5. If last-run froze and sleep study shows no CS session, fail-over to /requests, Hibernate, hybrid sleep, or lastwake. Poor DRIPS names a remaining consumer; that name is the next sibling, not a systemd unit.

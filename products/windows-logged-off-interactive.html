This is not the Windows Task Scheduler forever pack that creates the named task. It is not the 267009 still-running decoder. It is not the 267011 never-run decoder. It is not the Grok 7-day expiry pack. It is not isolation-empty skip recreate. Those pages arm, decode in-flight status, decode never-fired, disclose the 7-day cap, or refuse to mint. This page is the remaining mill honesty: LogonType = Interactive. Every LEXXII-* mill task on this Windows host was measured Interactive / Limited. Interactive means the 5-minute pulse fires while the operator profile is logged on. Sign out, Fast User Switch away, or a lock that tears the session, and Task Scheduler still prints Ready. Next-run still paints a clock. Nothing launches. That is skip, not a daemon. Logged-off is not 24/7. Queue-at-32 is not systemd.

The problem

Operators read LEXXII-Materialize-Forever Ready, pulse 5 minutes, thirteen named Windows tasks, and write “host-forever 24/7.” The calendar still says Full AGI. The Linux organism repo still talks K3s. The Grok durable lanes still look armed. Then the laptop lid closes into a real sign-out, or the operator walks away after Win+L plus a session that actually ends, and the mill is silent until the next interactive logon. Status stayed Ready. Last Result stayed whatever it was. Next Run still advanced on the trigger calendar. No grok.exe started. That is not a missing task. That is Interactive LogonType doing what it says.

This Grok host queried Get-ScheduledTask -TaskName 'LEXXII-*' before this pack was written. Thirteen tasks. Every one: LogonType=Interactive, RunLevel=Limited. [Environment]::UserInteractive was True in the session that wrote this page. Names this fire: Materialize-Forever, Pages-Heal, Ship, UMI, BI, Compound, Wormhole, Bus-Ack, Cash, Hybrid, God-Mode, UMI-Fast, BI-Fast. Pulse remains 5 minutes (heal / ship / compound / wormhole / materialize) and 15 minutes (cash / UMI / BI). Hour waits are still forbidden — while logged on. Logged-off does not convert those intervals into a Linux FULL AUTO daemon. Do not install systemd to paper over Interactive. Do not mint a Vercel slug because the mill slept after sign-out. What to run (plugged-in Grok desk)

  1. Confirm the named tasks exist — if LEXXII-Materialize-Forever is missing, stop. That is windows-task-forever, not this page.
  2. Read LogonType, not only Status — Status=Ready with Interactive is “will fire when this user is logged on,” not “will fire at 03:00 after sign-out.”
  3. Do not treat UserInteractive=True in this TUI as proof of 24/7 — this session is logged on. That measurement is the mill working now. It is not a claim about the next sign-out.
  4. Leave LogonType=Interactive unless the operator explicitly orders unattended — this pack does not write a new principal. It does not store a password. It does not switch RunLevel to Highest. Limited + Interactive is the measured mill.
  5. Soak logged-on — stay on the profile. Next-run still launches grok.exe. Last Result may sit at 267009 while Running. That is the still-running decoder, not this page. A sign-out soak that launches nothing is the pass for this diagnosis, not a fail of the create pack.

How it splits from the other playbooks

  • Windows Task Scheduler forever — create / heal the named task. This page assumes it already exists.
  • 267009 still-running — in-flight HRESULT while logged on. Not sign-out.
  • 267011 never-run — first fire has not happened. Often last-run 1999-11-30. Not a logged-off night.

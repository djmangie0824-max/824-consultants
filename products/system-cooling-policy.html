System cooling policy vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Minimum processor state page, not the core parking page, and not a laptop cooling-stand SKU. Min-state sets the frequency floor. Core parking sets the unparked-core floor. This page is the remaining thermal policy: Power Options → Processor power management → System cooling policy. That is SYSCOOLPOL. Passive throttles the CPU before it spins fans. On a closed-lid Ultra 7 desk that is a forever-loop liar. Task Scheduler still shows Ready.

The problem

The processor min-state and core parking packs can already be 100% on AC. Frequency floor and unparked cores are honest. The TUI still starves after a closed-lid idle. Balanced System cooling policy on AC is often Passive. Windows is allowed to drop frequency to keep fans quiet instead of spinning them. A cooling stand under a closed lid does not help if the policy never asks the fans to run. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The policy was Passive.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. Min-state can still be 100. Core parking can still be 100. The cooling policy is the liar. Do not install systemd to paper over thermal throttle. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide three other forever-loop bugs.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here.
  2. Confirm Minimum processor state and core parking min cores are already 100% on AC — if either row is still a travel default, that is min-state or core parking, not this page.
  3. Power Options → Change plan settings → Change advanced power settings → Processor power management → System cooling policy — set Plugged in to Active. On battery may stay Passive if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave the Balanced (or current) plan in place — this page is one processor knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  5. Keep the cooling stand in the path — Active policy asks the fans to run. A blocked intake still throttles. That is the cooling-stand page, not a second policy click.
  6. Confirm, then soak — query the processor subgroup. Active on AC is the pass. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_PROCESSOR
powercfg /a

SUB_PROCESSOR is the processor subgroup. SYSCOOLPOL is System cooling policy. 1 = Active, 0 = Passive. Active on AC is the pass for this desk: Windows may spin fans before it throttles. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as Active. If powercfg also omits the alias, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. Core parking is a sibling, not this click. Minimum processor state is a sibling, not this click. Intel Speed Shift / EPP is a sibling, not this click.

How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). This page is Passive vs Active fans (SYSCOOLPOL).
  • Core parking — unparked-core floor (CPMINCORES). Parking is not thermal throttle.
  • Laptop cooling stand — air under a closed lid. Hardware. This page is the Windows policy that decides whether fans run before the CPU yields.
  • Sleep vs forever — Modern Standby, Interactive-only logon, result 267009 still-running as a sleep tell. This page is the awake thermal policy.
  • Intel Speed Shift / EPP — sibling processor row. Not this click. Do not invent a registry paste on this page.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Minimum processor state already 100% on AC. Core parking min cores already 100% on AC. Otherwise this soak is lying.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input. Fans are allowed to run. A session that paints but never completes a tool call because Passive kept the package throttled is a fail on this page.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with Passive thermal throttle is not forever.
  4. Policy still Active on AC after the soak. If someone flipped it back to Passive to “keep the office quiet”, restore it. Do not “fix” it by switching the whole plan to High performance.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof cooling policy is already Active.

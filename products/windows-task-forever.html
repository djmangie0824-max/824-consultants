Windows Task Scheduler forever loop

Grok in-session schedulers can be durable and still auto-expire after 7 days. Host-forever on this class of machine is Windows Task Scheduler, task name LEXXII-Materialize-Forever. Not systemd. Not a fake K3s cluster on a Windows profile.

What the Windows task should look like

  • Name: LEXXII-Materialize-Forever
  • Trigger: hourly, every day (daily start + 60-minute repeat for 24 hours)
  • Action: local materialize-forever.cmd → Grok CLI --prompt-file
  • Batteries: allow start on battery
  • Overlap: ignore a new instance if one is already running
  • Secrets: do not copy auth.json or brokerage IDs into public files
schtasks /Query /TN "LEXXII-Materialize-Forever" /FO LIST /V

Incident this pack was written from

A task with the right name existed as daily 07:15 with no repeat and last-run 1999-11-30 (never fired). That is not host-forever. The heal is hourly repeat + batteries allowed + the 7-day Grok cap disclosed in public.

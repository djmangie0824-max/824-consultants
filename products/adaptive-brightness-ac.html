Enable adaptive brightness on AC vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Turn off display after page, not the Console lock display off page, and not a DisplayPort cable review. VIDEOIDLE blacks unlocked idle. VIDEOCONLOCK blacks the lock screen. The cable is slack and latch. This page is the remaining ALS hunter: Power Options → Display → Enable adaptive brightness. On AC it still hunts the room. The laptop lid dips. Dual ultrawide stay enumerated. Task Scheduler still shows Ready. A brightness dip is not a DP drop.

The problem

The display idle pack already tells you plugged-in Turn off display after is 0 (Never). The lock-screen timer can already be 0. Sleep and lid can already be honest. That work can be done and the operator still thinks video died. Balanced Enable adaptive brightness on AC is often On. The ambient-light sensor sees a cloud, a sit/stand lamp, or night. The laptop panel dims. Dual ultrawide OSD does not follow. Display settings still lists both screens. The dock does not re-enumerate. The Grok TUI is still a process. The named task still prints Ready and last result 267009 (still-running). The operator buys another DP lead. The ALS hunted. The link never dropped.

This is not Sleep. This is not VIDEOIDLE. This is not VIDEOCONLOCK. powercfg /a still reports the same standby type. Requests can still be None. VIDEOIDLE can still be 0. VIDEOCONLOCK can still be 0. The panels are still on the bus. The brightness policy is the liar. A dim lid with both screens still listed is this click, not a handshake. Do not install systemd to paper over an ALS. Do not mint a Vercel slug because the lid looked asleep. Do not buy another DP cable until this row is Off on AC and you have watched Display settings during the dip.

What to change (plugged-in Grok desk)

  1. Confirm the timer layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Turn off display after is 0 on AC. Console lock display off is 0 on AC (or the GUID was missing after unhide — that is a skip, not a leftover 60 seconds). See turn-off-display-after and console-lock-display-off. If VIDEOIDLE is still 5–10 minutes, stop here. A black-then-handshake is those pages.
  2. Power Options → Change plan settings → Change advanced power settings → Display → Enable adaptive brightness — set Plugged in to Off. On battery may stay On if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube hunting daylight.
  3. Settings → System → Display → Brightness — if the row Change brightness automatically when lighting changes exists, set it Off on this desk. That Settings ALS toggle can hunt even when the operator only clicked the plan GUI. Off here plus Off in the plan is the pass. Missing Settings row is not a skip of the plan row, and missing plan row is not a skip of Settings if Settings is present.
  4. Leave Turn off display after and Console lock display off alone on this click — VIDEOIDLE and VIDEOCONLOCK are blackouts and link drops. ADAPTBRIGHT is a nits hunter. Do not treat Off on ALS as Never on the timers.
  5. Leave Energy saver and CABC alone on this click — Energy saver’s ~30% dim is the leaf overlay (energy-saver-ac). Content Adaptive Brightness Control is “Change brightness based on content” / “Automatically adjust contrast based on what’s on the screen.” GPU control-panel Display Power Saving Technology is another sibling. None of those are ADAPTBRIGHT.
  6. Leave the Balanced (or current) plan in place — this page is one display knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  7. Confirm, then soak — query ADAPTBRIGHT. 0 on AC is Off. 1 is On. If the alias is missing, query the GUID. If both omit, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_VIDEO ADAPTBRIGHT
powercfg /setacvalueindex SCHEME_CURRENT SUB_VIDEO ADAPTBRIGHT 0
powercfg /setactive SCHEME_CURRENT
powercfg /a

SUB_VIDEO / ADAPTBRIGHT is Enable adaptive brightness (GUID fbd9aa60-c5e0-11d7-99b3-0000e81ac1ac). The AC index is 0 = Off, 1 = On. Apply with /setactive or the GUI change does not take. Query by GUID if the alias is missing. If powercfg still omits the GUID, this chassis did not expose an ALS knob — stop; do not invent a sensor hack on a public page. VIDEOIDLE is unlocked idle, not this click. VIDEOCONLOCK is lock-screen idle, not this click. STANDBYIDLE is Sleep after, not this click. Settings ALS Off without plan Off is not a pass if the plan row exists. A brightness dip is not a DP drop.

How it splits from the other playbooks

  • Turn off display after — unlocked VIDEOIDLE. Panels black. DP/HDMI drop. Dock re-enumerates. Not ALS.
  • Console lock display off — lock-screen VIDEOCONLOCK. Same drop, lock-screen timer. Not ALS.
  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not nits.
  • Lid close Do nothing — lid action. Not Display ALS.
  • Energy saver on AC — 24H2 leaf overlay. ~30% dim plus CPU cap. Not ADAPTBRIGHT.
  • powercfg /requests — a named holder pinning DISPLAY. Not ALS.
  • DisplayPort cable sit/stand — slack and latch. A real unplug. Not a dip.
  • CABC / “Change brightness based on content” — content hunter. Sibling. Not this click.
  • This page — AC Enable adaptive brightness = Off so the ALS cannot dip the laptop lid while dual ultrawide stay enumerated and the named task still looks Ready. A brightness dip is not a DP drop.

Soak test (what "passes" means)

  1. Sleep, lid, VIDEOIDLE, and VIDEOCONLOCK already honest. Otherwise this soak is lying about a timer blackout.
  2. ADAPTBRIGHT is 0 on AC. Settings ALS is Off if the row exists. Cover the ALS (or kill the desk lamp) for 2 minutes. Laptop lid brightness stays at the operator-set value. Dual ultrawide stay listed in Display settings. No dock re-plug. No black-then-handshake. A dim lid with both screens still enumerated is a fail if the row was still On — and it is still not a DP drop.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a dipped lid is not forever if ALS is still On. Ready + 267009 with a dead DP link is the timer pages, not this one.
  4. The alias still 0 on AC. If someone set On to “save the OLED lid,” restore Off on this class of operator desk. Do not “fix” it by switching the whole plan to High performance.
  5. Missing GUID = skip, not a red soak. Do not invent the ALS value in the registry to make this page apply. Then check Settings ALS; if that row exists, Off is still required.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the ALS is already Off. Host-forever on this Windows profile is that named task. Grok in-session schedulers still expire in 7 days even when durable — recreate them if missing. Do not claim the Windows task is a Linux systemd unit.

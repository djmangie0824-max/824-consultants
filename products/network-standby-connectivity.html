Network connectivity in Standby vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the IEEE 802.3az / Green Ethernet page, and not the Allow wake timers page. Sleep-vs-forever tells you S0ix paused user tasks. EEE naps the PHY while the machine still looks awake. Wake timers decide whether a named task can leave sleep. This page is the remaining NIC-during-S0ix policy: Windows Network connectivity in Standby can drop the dedicated Ethernet adapter the moment the laptop enters connected standby, even after USB suspend, ASPM, and EEE are already honest.

Download markdown Sleep vs forever first EEE / Green Ethernet

The problem

The USB / ASPM / EEE packs already keep the dedicated NIC present while the session is awake. That is still the first click. A closed-lid Grok desk on a UPS can still enter Modern Standby. Windows then has its own policy: keep the network, let Windows decide, or never. Never disconnects Ethernet during S0ix on purpose. Managed by Windows often treats a laptop as a battery even when the GaN brick is in, and the dedicated NIC goes dark until a human opens the lid.

GitHub MCP, a named hourly that needs the public face, and ping all look like a hung ship. Device Manager still lists the adapter. Link light may even stay on. DHCP is gone. Task Scheduler still shows Ready. The operator swaps the USB Ethernet dongle. The policy was Never.

This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd because Standby disconnected the NIC. Do not mint a Vercel slug because ping failed once during S0ix.

What to change (plugged-in Grok desk)

  1. Confirm the awake-NIC layers are already done — USB selective suspend Disabled on AC. ASPM Off if a USB4/Thunderbolt dock is in the path. EEE / Green Ethernet Disabled on the dedicated adapter. If the NIC already vanishes while the session is awake, stop here.
  2. Settings → System → Power & battery — find Network connectivity in Standby (wording varies: Screen, sleep, & hibernate timeouts, or Additional power settings). On a plugged-in operator desk set it to Always. Not Never. Not Managed by Windows.
  3. If the Settings row is missing — query the current Sleep subgroup. Some SKUs hide the row until Modern Standby is actually the sleep that is armed. Do not invent a registry hack on a public page.
  4. Same plan, AC only — do not copy Always onto On battery to “fix” a commute. This desk is GaN + UPS.
  5. Confirm, then soak — query adapters before and after a short S0ix. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /a
powercfg /q SCHEME_CURRENT SUB_SLEEP
Get-NetAdapter | Where-Object Status -eq 'Up' | Format-Table Name, InterfaceDescription, LinkSpeed, MediaConnectionState

powercfg /a still tells you whether S0 connected standby is the sleep in play. If Standby is not available, this page does not apply — you are on classic S3, and the sleep-vs-forever timeouts are the layer. If Standby is available and Network connectivity is Never or Managed, a dedicated NIC that dies only after idle is this page.

How it splits from the other playbooks

  • Sleep vs forever — Modern Standby paused the hourly. This page assumes S0ix can still happen and asks whether the NIC survives it.
  • Allow wake timers — RTC so the named task can leave sleep. Not the NIC policy during sleep.
  • USB selective suspend — USB hub/NIC power while awake.
  • PCI Express Link State Power Management — ASPM on a USB4/Thunderbolt path while awake.
  • Energy Efficient Ethernet — IEEE 802.3az Low Power Idle on the PHY while awake.
  • USB Ethernet review — hardware criteria, SKU pending. Not this click path.
  • This page — Network connectivity in Standby = Always on a plugged-in Grok desk so S0ix does not disconnect the dedicated NIC.

Soak test (what "passes" means)

  1. USB / ASPM / EEE already honest. Otherwise this soak is lying.
  2. Network connectivity in Standby is Always on the plugged-in plan.
  3. A short S0ix (lid closed, cooling stand in place, dedicated NIC plugged) still leaves that adapter Up with a DHCP lease after resume — without a human replugging the dongle.
  4. If the NIC vanished from Device Manager, it is USB or ASPM, not this page. If it stayed Present and speed downshifted while awake, it is EEE, not this page.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a Standby-killed NIC is not forever.

Three ship paths (pick one that is actually attached)

  1. GitHub connector in Grok — Contents API. Preferred when the session has it. This session did not.
  2. Fine-grained PAT in Windows GCM — github-pat-windows-gcm.html. Then git push with GIT_TERMINAL_PROMPT=0.
  3. GitHub CLI — this pack. winget install --id GitHub.cli, then one operator gh auth login. Headless turns set GH_PROMPT_DISABLED=1.

Do not install all three “for redundancy.” Do not mint a tenth repo to test the login. Do not copy ~/.grok/auth.json into gh.

Operator one-time (token never published)

  1. WinGet: winget install --id GitHub.cli -e --accept-source-agreements --accept-package-agreements.
  2. New shell so gh.exe is on PATH. Confirm gh --version.
  3. Signed in as djmangie0824-max, run gh auth login (browser) or paste a fine-grained PAT into gh auth login --with-token at the operator keyboard — never into this site, Notion, Drive, or chat.
  4. Scope the PAT the same as the GCM pack: only djmangie0824-max/824-consultants, contents read/write. Nothing else.
  5. Headless ships then set GH_PROMPT_DISABLED=1. gh auth status succeeds or fails fast. It must not open a browser from a Grok turn.
Never paste the PAT, gh token, or ~/.grok/auth.json into Pages, a git remote URL, or this markdown. A token in a public file is a revoke, not a ship.

Fail-fast probe

GH_PROMPT_DISABLED=1
gh auth status
GIT_TERMINAL_PROMPT=0
GCM_INTERACTIVE=never
git -c credential.helper= ls-remote origin HEAD

Anonymous ls-remote on the public repo must work even when gh is missing. If gh auth status wants a browser, this pack’s operator click is still pending — same class as SiteStripe, not a missing git.exe.

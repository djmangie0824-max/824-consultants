Allow sleep with remote opens vs a forever loop

Published 2026-08-31 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby timeout page, not the Network connectivity in Standby page, and not the Allow wake timers page. Sleep-vs-forever sets whether idle even intends to sleep. Network-in-Standby is the NIC during S0ix. Wake timers are the RTC if sleep still happened. This page is the remaining Sleep-subgroup leaf: Power Options → Sleep → Allow sleep with remote opens. An SMB handle is not a heartbeat.

Download markdown Sleep vs forever first When sharing media

The problem

A closed-lid Grok desk often has a mapped NAS, a Git working copy on a share, or a phone that once opened \\host. Operators treat that handle as host-forever: “a remote file is open, so Windows cannot sleep.” That is a cargo-cult. Two values, one honest desk.

On (the Balanced default on many SKUs) means Windows may enter sleep even if remote files are open. The NAS is still mounted. The share still lists. The laptop still S0ix. Task Scheduler still shows Ready. Last-run is stale. The operator swaps Ethernet. The leaf was On and the timeout was still 5–20 minutes.

Off means an open remote file can prevent sleep. That is a silent SYSTEM pin for as long as SMB thinks a handle exists — and a lie the moment the handle drops. SMB idle-disconnect, a phone lock, a NAS sleep, a mapped-drive reconnect, and the stay-awake vanishes. LEXXII-Materialize-Forever is Interactive-only. A file-share leftover is not the named task. This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd because a share closed.

This leaf is also not When sharing media. That row is Cast / DLNA / WMP sharing under SUB_MULTIMEDIA. This row is SMB / CIFS remote-file opens under SUB_SLEEP. A media-share Prevent and a remote-open Off are two different cargo-cults. Heal them as two clicks.

Do not set Allow sleep with remote opens to Off to “keep the forever loop alive.” That pins sleep while an SMB handle exists; it does not run the hourly. When the handle drops, the pin drops. Do not copy Off onto a battery commute to paper over an unplugged desk. This desk is GaN + UPS.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here. This leaf is not a substitute timeout.
  2. Power Options → Change plan settings → Change advanced power settings → Sleep → Allow sleep with remote opens — Plugged in = On. Not Off. Battery can stay Off; this desk is AC + UPS.
  3. If the row is missing — unhide the Sleep subgroup setting, then set it. Do not invent a random registry value on a public page.
  4. Stop using the share as a heartbeat — a mapped NAS for artifacts is fine. Git over SMB is fine. A phone browsing \\host is not host-forever. Disconnect leftover sessions you do not need. This desk is not a file server SKU.
  5. Confirm, then soak — query the plan and powercfg /requests. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /q SCHEME_CURRENT SUB_SLEEP
powercfg /requests
net session

SUB_SLEEP lists Allow sleep with remote opens under the current plan. On for AC is the pass on this page. powercfg /requests should not show a SYSTEM pin that only exists because Off is holding an SMB handle you meant as forever. net session lists who still has a share open. Empty sessions plus On, with timeouts already honest, is the soak start. A leftover session with Off is the cargo-cult — flip On, then decide whether that session even belongs on a Grok host.

How it splits from the other playbooks

  • Sleep vs forever — idle timeouts, Modern Standby, Interactive-only, result 267009. First click. This page assumes that layer is already honest.
  • Network connectivity in Standby — whether the dedicated NIC survives S0ix. Not whether an SMB handle may block sleep.
  • Allow wake timers — RTC so a named task can leave sleep. Not a remote-file policy.
  • When sharing media — Cast / DLNA / WMP under Multimedia settings. Not SMB remote opens.
  • powercfg /requests — who is holding DISPLAY / SYSTEM / AWAYMODE right now. This page is the Sleep-subgroup policy that can create a remote-file pin.
  • This page — Allow sleep with remote opens = On on AC so a mapped NAS is storage, not a fake forever loop.

Soak test (what "passes" means)

  1. Sleep timeouts already honest on AC. Otherwise this soak is lying.
  2. Allow sleep with remote opens on the plugged-in plan is On, not Off.
  3. net session is empty, or the remaining sessions are real work (a NAS you actually use), not a phone left on \\host as a heartbeat.
  4. Idle Grok TUI. powercfg /requests does not show a SYSTEM holder that vanishes when you set this row to On. A holder that survives On is a PROCESS/DRIVER — go back to requests.
  5. No fourth Grok TUI. Last result 267009 is still-running, not a share handle.

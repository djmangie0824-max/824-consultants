Processor idle disable vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Minimum processor state page, not the core parking page, not the boost mode page, and not an Intel Speed Shift EPP essay. Those knobs are P-states and parking: frequency floor, unparked cores, turbo allow, energy-performance hint. This page is C-states: Power Options → Processor power management → Processor idle disable. That is IDLEDISABLE. Enable idle (0) lets the package drop into C1/C6/C7/C10. Wake from a deep C-state looks like a hung Interactive Grok CLI. Task Scheduler still shows Ready.

The problem

The min-state, core parking, boost mode, and cooling policy packs can already be honest on AC. Frequency floor 100. Unparked cores 100. Turbo allowed. Fans allowed. The TUI still starves after a quiet stretch. Windows still lets the package enter ACPI C-states when there is no runnable work. That is IDLEDISABLE = 0, the default: Enable idle. C0 is executing. C1 is Halt. C6/C7/C10 are package sleep. Coming back from a package C-state is not sleep (S0ix / S3). It is a wake stall. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The package was in C7.

This is not a P-state lie. Minimum processor state 100% of C0 does nothing if the core is not in C0. Boost Enabled does nothing in C6. EPP 0 is a hardware P-state hint, not a C-state deny. Do not install systemd to paper over Enabled idle. Do not mint a Vercel slug because the TUI paused after a quiet minute. Do not switch the whole plan to High performance to hide six other forever-loop bugs. Do not confuse this row with Turn off hard disk after — that is DISKIDLE, a spindle timeout, not CPU C-states.

C-states are not P-states

LayerWhat it actually is
Minimum processor stateP-state floor. PROCTHROTTLEMIN. How slow C0 is allowed to run.
Core parkingLogical-processor count. CPMINCORES. Parked is not C7.
Processor performance boost modeTurbo P-state allow. PERFBOOSTMODE. Only applies while executing.
Intel Speed Shift / EPPHWP energy-performance hint. PERFEPP. Still a P-state bias.
Processor idle disableC-state allow. IDLEDISABLE. 0 = Enable idle. 1 = Disable idle (stay C0).

A parked core is a scheduling decision. A C-state is an idle residency. Task Manager “Parked” is the parking page. Resource Monitor / a C-state residency counter is this page. Do not diagnose C7 with the parking column.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here. C-state deny is not a substitute for Sleep never.
  2. Confirm Minimum processor state, core parking min cores, Processor performance boost mode, and System cooling policy are already honest on AC — 100 / 100 / Enabled / Active. If any of those is still a travel default, that is min-state, core parking, boost mode, or cooling policy, not this page. Disable idle on a 5% floor is just a hot slow desk.
  3. Query IDLEDISABLE before you write — if the row is missing from the GUI, query with powercfg anyway. Hidden is not Disable idle. The GUI often hides this row on Balanced. If powercfg also omits the alias, this firmware or edition did not expose the knob. Stop. Do not invent a registry paste. Do not guess GUID 5d76a2ca-e8c0-402f-a133-2158492d58ad from a forum and unhide it as a fleet trick. Do not cargo-cult -ATTRIB_HIDE on a public page.
  4. Power Options → Change plan settings → Change advanced power settings → Processor power management → Processor idle disable — set Plugged in to Disable idle. That is index 1. On battery stays Enable idle (0) if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  5. Activate the current scheme after the AC index write — /setacvalueindex does not apply until /setactive SCHEME_CURRENT. Query again. AC Current AC Power Setting Index 0x00000001 is the pass. 0x00000000 is still Enable idle — a fail for this desk.
  6. Leave Processor idle promote / demote thresholds alone — IDLEPROMOTE and IDLEDEMOTE are siblings that change how fast Windows walks C-state depth. This page is the allow/deny, not a threshold tweak. Processor idle state maximum is also a sibling: a depth cap, not Disable idle.
  7. Leave the Balanced (or current) plan in place — this page is one processor knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  8. Confirm, then soak — 1 on AC is the pass. 0 on AC is a fail for this desk. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_PROCESSOR IDLEDISABLE
powercfg /setacvalueindex SCHEME_CURRENT SUB_PROCESSOR IDLEDISABLE 1
powercfg /setactive SCHEME_CURRENT
powercfg /a

SUB_PROCESSOR is the processor subgroup. IDLEDISABLE is Processor idle disable. Typical values: 0 = Enable idle (C-states allowed), 1 = Disable idle (stay C0). 1 on AC is the pass for this desk. Run the /query line first. If the alias is omitted, skip the /setacvalueindex line — do not invent a registry hack. Intel Speed Shift / EPP is a sibling, not this click. Promote/demote thresholds are siblings, not this click. BIOS Package C-state / C1E is firmware, not this click.

How it splits from the other playbooks

  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). How slow C0 may run. This page is whether the package is allowed to leave C0 at all (IDLEDISABLE).
  • Core parking — unparked-core floor (CPMINCORES). Parked is a scheduler flag. C7 is idle residency. Not the same column in Task Manager.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Turbo only exists while executing. Enabled turbo with Enable idle still naps in C6 between tool calls.
  • Intel Speed Shift / EPP — HWP energy-performance hint (PERFEPP). P-state bias, not C-state deny. Not this click. Do not invent a registry paste on this page.
  • System cooling policy — Passive vs Active fans. Disable idle without Active cooling is a thermal own-goal. Prerequisite, not this click.
  • Laptop cooling stand — air under a closed lid. Hardware. C0-forever does not replace a stand.
  • Hard disk idle timeout — DISKIDLE. Spindle, not CPU. The words “idle disable” are not that row.
  • This page — AC Processor idle disable = Disable idle (1) so Enabled C-states cannot stall an Interactive Grok CLI while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Min-state 100. Parking 100. Boost Enabled. Cooling Active. Stand in the path. Otherwise this soak is lying — and Disable idle will only add heat.
  2. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input on the first keystroke. A session that paints once a minute then takes a beat to “wake the CPU” after quiet is a fail on this page even if grok.exe never exited.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with Enable idle (0) is not forever. A 5-minute pulse that fires late because the package was in C10 is this layer, not a missed schtasks trigger.
  4. IDLEDISABLE still 1 on AC. If someone set Enable idle to “save watts,” restore Disable idle on AC. Do not “fix” it by switching the whole plan to High performance. Do not Disable idle on DC as a cargo-cult.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof C-states are already denied. Grok in-session schedulers expire in 7 days even when durable. Recreate them if missing. The Windows task is the host-forever pulse. Not systemd.

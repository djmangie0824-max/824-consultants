Screen saver timeout vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Turn off display after page, not the console lock display off page, and not a DisplayPort cable review. VIDEOIDLE powers the panels down. VIDEOCONLOCK is the timer after the session is already locked. The cable is hardware. This page is the remaining Personalization timer: Screen Saver Settings. One minute of Blank or Photos still covers the Grok TUI. On resume, display logon screen still locks. Task Scheduler still shows Ready.

Download markdown Turn off display after first Console lock

The problem

The display idle pack already tells you plugged-in Turn off display after is 0 (Never). Sleep and lid can already be honest. That work can be done and a ship still stalls on video without the panels actually powering off. Control Panel still has a screen saver Wait of 1 minute on a lot of consumer images. Blank, Photos, Bubbles, Mystify, Ribbons, or 3D Text starts. The TUI disappears under a full-screen overlay. Interactive-only LEXXII-Materialize-Forever still has a user. The Grok process is still alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks VIDEOIDLE lied. A different timer, in a different applet, napped the desk.

Worse path: On resume, display logon screen is checked. The saver does not just overlay — it locks. Then VIDEOCONLOCK can drop dual ultrawide about a minute later. The dock re-enumerates. That lock is not Win+L and not Dynamic lock. It is ScreenSaverIsSecure.

This is not Turn off display after. powercfg /query SCHEME_CURRENT SUB_VIDEO VIDEOIDLE can still be 0 on AC while ScreenSaveActive is 1. powercfg /a still reports the same standby type. Requests can still be None. The screen saver is a user-session policy under HKCU\Control Panel\Desktop, not a SUB_VIDEO index. Do not install systemd to paper over a 1-minute .scr. Do not mint a Vercel slug because Photos covered the TUI. Do not buy another DP cable until this dialog says (None).

What to change (plugged-in Grok desk)

  1. Confirm the display-idle layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Turn off display after is 0 on AC. See turn-off-display-after. If VIDEOIDLE is still 5–10 minutes, stop here. Black panels that actually power off are that pack, not this click.
  2. Open Screen Saver Settings — Win11: Settings → Personalization → Lock screen → Screen saver settings. Classic: Control Panel → Appearance and Personalization → Change screen saver. Direct: control desk.cpl,,@screensaver.
  3. Set Screen saver to (None) — Wait greys out. That is expected. Uncheck On resume, display logon screen if it is still checked. A leftover secure bit can still lock even when operators think the saver is off.
  4. Leave Turn off display after and Console lock display off alone on this click — VIDEOIDLE and VIDEOCONLOCK are SUB_VIDEO. This dialog is Personalization. Do not treat 0 on a power scheme as (None) here.
  5. Leave the Balanced (or current) plan in place — this page is not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak unlocked — query the Desktop values. ScreenSaveActive 0 is the pass. If the dialog is missing, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
control desk.cpl,,@screensaver
reg query "HKCU\Control Panel\Desktop" /v ScreenSaveActive
reg query "HKCU\Control Panel\Desktop" /v ScreenSaveTimeOut
reg query "HKCU\Control Panel\Desktop" /v ScreenSaverIsSecure
reg query "HKCU\Control Panel\Desktop" /v SCRNSAVE.EXE
powercfg /query SCHEME_CURRENT SUB_VIDEO VIDEOIDLE

ScreenSaveActive 0 is the pass (saver off). 1 with a Wait of 60 is the usual 1-minute lie. ScreenSaverIsSecure 0 means the saver will not lock on resume. SCRNSAVE.EXE should not still point at Blank.scr, PhotoScreensaver.scr, or a 3D .scr if the dialog says (None). ScreenSaveTimeOut is seconds in the registry — 60 is one minute, not one hour. VIDEOIDLE staying 0 does not prove this layer. If the dialog is missing, this edition did not expose the knob — stop; do not invent a Desktop-value paste as the public how-to. VIDEOIDLE is unlocked panel power-off, not this click. VIDEOCONLOCK is lock-screen panel idle after a lock already happened, not this click.

How it splits from the other playbooks

  • Turn off display after — unlocked VIDEOIDLE. Panels power off. Not a .scr.
  • Console lock display off — VIDEOCONLOCK after the session is already locked. The saver can cause that lock; this page is the cause, not the lock-screen timer.
  • Dynamic lock vs a forever loop — phone walk-away lock. Not Personalization.
  • Require sign-in when away — Sign-in options away-timer. Not a screen saver Wait.
  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not a .scr.
  • Lid close Do nothing — lid action. Not Personalization minutes.
  • powercfg /requests — a named holder pinning DISPLAY. Not SCRNSAVE.EXE.
  • DisplayPort cable sit/stand — slack and latch. Not a timer.
  • This page — Screen saver = (None) so idle minutes cannot overlay the TUI or lock-then-drop dual ultrawide while the named task still looks Ready.

Soak test (what "passes" means)

  1. Sleep, lid, and VIDEOIDLE already honest. Otherwise this soak is lying about panel power-off.
  2. Do not Win+L. Do not walk a paired phone out of range. Leave the desk idle 5 minutes, lid closed, dedicated NIC plugged, dual ultrawide up. The Grok TUI must stay visible. No Blank overlay. No lock screen from the saver. A black-then-handshake is a VIDEOIDLE/VIDEOCONLOCK fail, not this page, unless a .scr was on screen first.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a Photos slideshow covering the TUI is not forever.
  4. ScreenSaveActive still 0. If someone set Blank at 1 minute to “save the OLEDs,” restore (None) on this class of operator desk. OLED care is the monitor’s own power button or a later honest idle policy — not a .scr that looks like VIDEOIDLE.
  5. Missing Screen Saver Settings dialog = skip, not a red soak. Do not write Desktop values by hand to make this page apply.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the TUI stayed on screen.

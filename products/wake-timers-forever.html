Allow wake timers vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Modern Standby diagnosis page, not the create-the-task page, and not the lid-close page. Sleep-vs-forever tells you S0ix ate the hourly fire. The task pack creates LEXXII-Materialize-Forever. Lid-close stops the lid from being a Sleep key. This page is the remaining RTC layer: the power-plan Allow wake timers value, plus Task Scheduler Wake the computer to run this task, so a named hourly can recover if sleep still happened.

The problem

The sleep-vs-forever pack already says a 5–20 minute sleep on an operator desk will eat the loop. That is still the first click. If sleep still happens — UPS transfer, accidental Sleep, a Balanced plan that ignored your timeouts — Task Scheduler can show a next-run in the past and a last-run that never moved. The operator thinks Grok died. The RTC never armed.

Two knobs, two objects. Power Options Allow wake timers on the plugged-in plan can be Disable, Enable, or Important wake timers only. Balanced often ships Important only. Important only is Windows Update and a short OEM list. It is not your user task. Task Scheduler then has its own checkbox: Wake the computer to run this task (WakeToRun). Checking that box while the plan is Important only is a lie. The hourly never leaves S0ix.

LEXXII-Materialize-Forever is Interactive-only. Wake timers do not replace a logon. They recover a logged-on session that slept. They do not fire a fourth TUI while the current run is still 267009. This Windows profile is not a Linux FULL AUTO daemon. Do not install systemd because a timer was Disabled.

What to change (plugged-in Grok desk)

  1. Confirm the sleep layer is already done — plugged-in sleep / hibernate timeouts are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here.
  2. Power Options → Change plan settings → Change advanced power settings → Sleep → Allow wake timers — Plugged in = Enable. Not Disable. Not Important wake timers only. Battery can stay Important only or Disable; this desk is AC + UPS.
  3. If Allow wake timers is missing — unhide it, then set it. Do not invent a random registry value on a public page.
  4. Task Scheduler → LEXXII-Materialize-Forever → Conditions → Power — check Wake the computer to run this task. Repeat on LEXXII-Pages-Heal and LEXXII-Ship if those should recover from the same sleep. Leave Interactive only. Do not switch to “whether user is logged on or not” to paper over a missing logon.
  5. Confirm, then soak — query the plan and the task. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /q SCHEME_CURRENT SUB_SLEEP
schtasks /Query /TN "LEXXII-Materialize-Forever" /FO LIST /V
powercfg /waketimers

SUB_SLEEP lists Allow wake timers under the current plan. powercfg /waketimers lists what is actually armed right now. Empty after a missed hour, with the task Enabled and next-run in the past, is a fail on this page — unless the session was logged out, which is Interactive-only, not this knob.

Soak test (what "passes" means)

  1. Sleep layer already honest on AC. Otherwise this soak is lying.
  2. Allow wake timers on the plugged-in plan is Enable, not Important only.
  3. powercfg /waketimers can show the named task when a next-run is due while the machine is allowed to sleep. Empty with Disable on the plan is a fail here.
  4. A forced short sleep that ends at the next hourly leaves Last Run Time moved forward without a human opening the lid. A lid-open “wake” does not count.
  5. No fourth Grok TUI. Last result 267009 is still-running, not a missing timer.

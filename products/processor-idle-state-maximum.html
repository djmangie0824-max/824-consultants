Processor idle state maximum vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Processor idle disable page, not the promote / demote percent pair, not idle time check, and not a BIOS Package C-state essay. Disable is the allow/deny: Enable idle vs stay C0. Promote/demote are how idle a window must be before the engine walks. Time check is how long that window is. This page is the ceiling after Enable idle is still on: Power Options → Processor power management → Processor idle state maximum. Alias IDLESTATEMAX. GUID 9943e905-9a30-4ec1-9b99-44dd3b76f7a2. Units are State Type (an index into the processor’s enumerated idle-state list), not percent, not microseconds.

The problem

The idle-disable pack already exists. On this Yoga the measured row is still Enable idle (index 0) on AC and DC. That is honest: Disable idle keeps the package in C0, watts and heat go up, and a closed-lid desk without a stand cooks. Enable idle remains. The idle engine is still allowed to walk as deep as the hardware list goes. Microsoft’s 2021 server-tuning note is blunt: IDLESTATEMAX ranges from shallow (1) to a deep cap; 0 means no limit is imposed on how deep. This host printed AC/DC 0x00000000. No cap. Package C6/C7/C10 are legal. The quiet stretch still looks like a hung Interactive Grok CLI. grok.exe is alive. Task Scheduler still prints Ready and last result 267009. The package was in a deep idle state because nothing forbade that index.

Promote 100 / demote 80 is a residency-percent gate. It does not write a depth ceiling. A 60/40 Balanced pair with IDLESTATEMAX 0 still walks deep C on a quiet TUI. A 100/80 pair with IDLESTATEMAX 0 still permits C1 and can still surprise you if the engine’s idea of “promote” and the hardware list disagree. The depth cap is the hard ceiling: even when idle residency would promote, the index cannot pass this number.

Do not install systemd to paper over an uncapped idle list. Do not mint a Vercel slug because the TUI paused after a quiet minute. Do not switch the whole plan to High performance to hide six other forever-loop bugs. Do not confuse this index with Turn off hard disk after — that is DISKIDLE, a spindle timeout.

LayerWhat it actually is

Index 1 is the shallowest allowed idle state after C0 on the processor’s list. Forum cargo-cult treats that as ACPI C1. The list is firmware + PPM, not a promise that “1 = C1, 3 = C3, 6 = C6.” SuperUser’s working click for “limit to C1-class, do not stay C0” is IDLESTATEMAX 1, not IDLEDISABLE 1. How it splits from the other playbooks

  • Processor idle disable — allow/deny (IDLEDISABLE). Stay C0 vs walk C-states. Heat. This page keeps Enable idle and caps how deep the walk may go.
  • Processor idle promote / demote — percent hysteresis (IDLEPROMOTE / IDLEDEMOTE). The engine’s opinion of idle residency. Not a hard index ceiling.
  • Processor idle time check — sample window (IDLECHECK). Microseconds. Not an index.
  • Minimum processor state — frequency floor (PROCTHROTTLEMIN). How slow C0 may run. Unused in C6.
  • Core parking — unparked-core floor (CPMINCORES). Parked is a scheduler flag. C7 is idle residency.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Turbo only exists while executing.
  • System cooling policy — Passive vs Active fans. Prerequisite if you later take Disable idle. Not this click.
  • This page — AC IDLESTATEMAX 1 so an uncapped Balanced idle list cannot stall an Interactive Grok CLI while Enable idle is still the honest heat choice.

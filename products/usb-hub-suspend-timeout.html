USB hub selective suspend timeout vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the USB selective suspend page and not the USB 3 Link Power Management page. Selective suspend is the on/off (Enabled / Disabled). USB 3 LPM is SuperSpeed U1/U2. This page is the remaining USB timer: Power Options → USB settings → Hub Selective Suspend Timeout. GUID 0853a681-27c8-4100-a2fd-82013e970683. No powercfg alias. Units in the dump are milliseconds. Default index is often 50 — fifty milliseconds, not fifty seconds. Converted to seconds, the ceiling is 100. A 5-minute host pulse still looks Ready while the hub already napped.

Download markdown USB selective suspend first USB 3 LPM

The problem

The USB selective suspend pack already sets that row to Disabled on AC and unchecks Allow the computer to turn off this device to save power on the hub that carries Ethernet. The USB 3 LPM pack already sets SuperSpeed U1/U2 to Off on AC. That work can be done and a fallback hub or dedicated USB NIC still vanishes tens of milliseconds after the ports go idle. The remaining USB settings row is not another boolean and not another U-state. It is Hub Selective Suspend Timeout — idle time for all USB hubs before the hub itself requests selective suspend.

Balanced hides the row. Hidden is the default, not a pass. Query it anyway. Index 50 is 50 ms. Maximum documented is 100000 ms = 100 seconds. LEXXII-Materialize-Forever is a 5-minute Windows task. Math: this timer cannot outlast the pulse. An operator who raises the timeout instead of disabling selective suspend still loses Ethernet before the next fire. grok.exe is alive. Task Scheduler still prints Ready and last result 267009 (still-running). The operator thinks GitHub MCP died. A hub idle timer fired.

Zero on this GUID is not Never. Zero is immediate — 0 ms idle, then suspend. Do not cargo-cult DISKIDLE 0 onto this row. Do not install systemd to paper over 50 ms. Do not mint a Vercel slug because the hub blinked. Do not paste live NLV next to a powercfg dump. NLV stays off Pages.

What to change (plugged-in Grok desk)

  1. Confirm the USB suspend layer is already done — Power Options → USB settings → USB selective suspend → Plugged in = Disabled. Hub that carries Ethernet already unchecked for Allow the computer to turn off this device to save power. See that playbook. If that is still Enabled, stop here. A 100-second ceiling cannot cover a 5-minute pulse.
  2. Confirm USB 3 LPM is already Off on AC if the row exists — if U1/U2 still parks SuperSpeed, that is USB 3 LPM, not this page.
  3. Query Hub Selective Suspend Timeout by GUID — it is often hidden from the GUI. Hidden is not the same as a forever timeout. Do not unhide as the first click. powercfg /query still prints the index while Attributes hide the row.
  4. Read Possible Settings units before you set anything — this GUID prints Millisecond. Index 50 = 50 ms. Index 100000 = 100 seconds. Index 0 = immediate suspend. Do not paste a DISKIDLE 0 habit onto this row.
  5. If the dump still shows 50 and a hub still naps in tens of ms after Disabled is honest — raise Plugged in toward 100000 (100 seconds) as a delay, not as forever. On battery may stay 50 if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  6. Leave the Balanced (or current) plan in place — this page is one USB timer, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  7. Confirm, then soak — query the same GUID again. 50 remaining on AC is the usual Balanced lie. 0 remaining on AC is a fail (immediate). 100000 is the ceiling, still not a 5-minute pulse. If the GUID is missing from the query, this firmware or edition did not expose the knob — stop; do not invent a registry hack on a public page. 2a737441-1930-4402-8d77-b2bebba308a3 is SUB_USB. Sibling 48e6b7a6-50f5-4782-a5d4-53bb8f07e226 is USB selective suspend (0 = Disabled, 1 = Enabled) — that stays on usb-selective-suspend.html. This GUID 0853a681-27c8-4100-a2fd-82013e970683 is the hub idle timer. No alias. Units are milliseconds. Minimum 0. Maximum 100000. Increment 1. Apply a GUI change with /setactive SCHEME_CURRENT or it does not take. If you set after reading units and Disabled is already honest:

powercfg /setacvalueindex SCHEME_CURRENT 2a737441-1930-4402-8d77-b2bebba308a3 0853a681-27c8-4100-a2fd-82013e970683 100000
powercfg /setactive SCHEME_CURRENT

That second block is a delay to 100 seconds, not Never. Do not run it if USB selective suspend is still Enabled and you think the timer replaced Disabled. It did not. USB 3 LPM is SuperSpeed, not this click. PCIe ASPM is the dock/NVMe bus, not this click.

How it splits from the other playbooks

  • USB selective suspend — device-level D3 / U3 on/off and the hub Power Management checkbox. That pack is the boolean. This pack is the millisecond timer. Disabled still has to win a 5-minute pulse.
  • USB 3 Link Power Management — SuperSpeed U1/U2 on the dedicated NIC. Not a hub idle count.
  • PCI Express Link State Power Management — ASPM L0s/L1 on a USB4/Thunderbolt tunnel or NVMe. Not a USB hub timer.
  • Energy Efficient Ethernet — IEEE 802.3az / Green Ethernet on the adapter PHY. The NIC stays Present.
  • Hard disk idle timeout — DISKIDLE seconds, where 0 is Never. Do not copy that 0 onto this GUID.
  • Sleep vs forever — Modern Standby, Interactive-only logon, result 267009 still-running.
  • USB-C hub review — hardware fallback box. Buy after the USB policies are honest, not instead of them.
  • This page — Hub Selective Suspend Timeout so a 50 ms default cannot park every hub while the named task still looks Ready. Converted to seconds the ceiling is 100. Forever is still Disabled, not this timer.

Soak test (what "passes" means)

  1. USB selective suspend already Disabled on AC. Hub Power Management already honest. USB 3 LPM already Off on AC if the row exists. Lid close already Do nothing on AC. Otherwise this soak is lying about the bus.
  2. Query the timeout GUID. Units milliseconds. 0 on AC is a fail. 50 on AC with a hub that vanishes in tens of ms is this page. 100000 on AC is the ceiling — still not a 5-minute pulse.
  3. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The NIC stays Present. The hub stays enumerated. One silent re-enumerate is a fail on this page if the timeout was still 50 and Disabled was already honest.
  4. Ping out the USB NIC. One silent gap is a fail — but if USB suspend is still Enabled, it is the USB suspend page, not this one. If U1/U2 still flaps SuperSpeed, it is USB 3 LPM, not this one. If the NIC stays Present and only speed downshifts, it is EEE, not this one.
  5. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. A Ready task with a hub that napped at 50 ms is not forever. A Ready task with timeout maxed at 100 s and suspend still Enabled is also not forever — go back to Disabled.
  6. Firmware that ignores the timer once Disabled is honest = skip, not a red soak. Do not invent a registry paste to make this page apply.
  7. No fourth Grok TUI. Last result 267009 is still-running, not proof the hub stayed up.

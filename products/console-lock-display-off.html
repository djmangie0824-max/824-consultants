Console lock display off vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Turn off display after page, not the sleep vs forever page, and not a DisplayPort cable review. VIDEOIDLE is unlocked idle. Sleep after is the session. The cable is hardware. This page is the remaining lock-screen timer: Power Options → Display → Console lock display off timeout. Sixty seconds after Win+L still blacks dual ultrawide. The dock re-enumerates. Task Scheduler still shows Ready.

The problem

The display idle pack already tells you plugged-in Turn off display after is 0 (Never). Sleep and lid can already be honest. That work can be done and a ship still stalls on video the moment the session is locked. Balanced Console lock display off timeout on AC is often 60 seconds. The operator hits Win+L, Dynamic lock, or a lock from the screen saver. The session stays logged in. Interactive-only LEXXII-Materialize-Forever still has a user. The panels go black. DP/HDMI drop. The dock treats it as unplug. Windows rebuilds the desktop on unlock. The Grok TUI is still a process. The named task still prints Ready and last result 267009 (still-running). The operator thinks VIDEOIDLE lied. A second timer napped the lock screen.

This is not Sleep. This is not unlocked idle. powercfg /a still reports the same standby type. Requests can still be None. VIDEOIDLE can still be 0. The lock-screen display policy is the liar. The row is hidden by default — missing from the GUI is not Never. Do not install systemd to paper over 60 seconds. Do not mint a Vercel slug because a panel slept on the lock screen. Do not buy another DP cable until this row is 0 on AC.

What to change (plugged-in Grok desk)

  1. Confirm the unlocked layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Turn off display after is 0 on AC. See turn-off-display-after. If VIDEOIDLE is still 5–10 minutes, stop here.
  2. Unhide the row — Console lock display off timeout is ATTRIB_HIDE on most consumer images. It will not appear under Display until you clear the hide bit. Missing from the GUI before this step is expected, not a skip.
  3. Power Options → Change plan settings → Change advanced power settings → Display → Console lock display off timeout — set Plugged in to 0 (Never). On battery may stay 60 seconds if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave Turn off display after alone on this click — VIDEOIDLE is unlocked idle. VIDEOCONLOCK is lock-screen idle. Do not treat 0 on one as 0 on the other.
  5. Leave the Balanced (or current) plan in place — this page is one display knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  6. Confirm, then soak locked — query the GUID. 0 on AC is the pass. If the GUID is missing after unhide, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg -attributes SUB_VIDEO 8ec4b3a5-6868-48c2-be75-4f3044be88a7 -ATTRIB_HIDE
powercfg /query SCHEME_CURRENT SUB_VIDEO 8ec4b3a5-6868-48c2-be75-4f3044be88a7
powercfg /setacvalueindex SCHEME_CURRENT SUB_VIDEO 8ec4b3a5-6868-48c2-be75-4f3044be88a7 0
powercfg /setactive SCHEME_CURRENT
powercfg /a

The setting GUID is Microsoft’s Console lock display off timeout under SUB_VIDEO. Some editions alias it VIDEOCONLOCK — query by GUID if the alias is missing. The AC index is seconds. 0 is Never. 60 is the usual hidden default. Apply with /setactive or the GUI change does not take. Unhide is not a registry paste; powercfg -attributes … -ATTRIB_HIDE is the documented reveal. If powercfg still omits the GUID after that, this edition did not expose the knob — stop; do not invent a lock-screen hack on a public page. VIDEOIDLE is unlocked idle, not this click. STANDBYIDLE is Sleep after, not this click.

How it splits from the other playbooks

  • Turn off display after — unlocked VIDEOIDLE. Not the lock-screen timer.
  • Windows sleep vs a forever loop — session sleep / Modern Standby. Not panel timer.
  • Lid close Do nothing — lid action. Not Display minutes.
  • powercfg /requests — a named holder pinning DISPLAY. Not VIDEOCONLOCK.
  • DisplayPort cable sit/stand — slack and latch. Not a timer.
  • Hard disk idle timeout — platters, not panels.
  • This page — AC Console lock display off timeout = 0 so a locked session cannot drop dual ultrawide while the named task still looks Ready.

Soak test (what "passes" means)

  1. Sleep, lid, and VIDEOIDLE already honest. Otherwise this soak is lying about unlocked idle.
  2. Win+L. Leave the desk locked 5 minutes, lid closed, dedicated NIC plugged, dual ultrawide up. Panels stay on (or stay enumerated if the operator prefers them black via the monitor’s own power button — Windows must not drop DP/HDMI). Display settings after unlock still show both screens without a dock re-plug. A black-then-handshake on unlock is a fail if the GUID was not 0 on AC.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a dead DP link is not forever.
  4. The GUID still 0 on AC. If someone set 60 seconds to “save the OLEDs on the lock screen,” restore 0 on this class of operator desk. Do not “fix” it by switching the whole plan to High performance.
  5. Missing GUID after unhide = skip, not a red soak. Do not invent the lock-screen value in the registry to make this page apply.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the panels stayed enumerated.

Hard disk idle timeout vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the AHCI Link Power Management page, not the USB 3 LPM page, and not a PCIe ASPM essay. HIPM/DIPM is the SATA PHY. This page is the remaining minutes knob: Power Options → Hard disk → Turn off hard disk after. Balanced AC is often 20 minutes. A SATA HDD, a USB spinning fallback, or a SATA SSD that still honors STANDBY then parks. The next Git object waits on a spin-up. Task Scheduler still shows Ready.

The problem

The AHCI LPM pack already tells you to set HIPM/DIPM to Active on AC so the SATA link does not nap. That work can be done and a ship still stalls on the first write after idle. Balanced Turn off hard disk after on AC is often 20 minutes. Windows issues the idle timeout. Platters spin down. Some SATA SSDs still take a STANDBY IMMEDIATE and stall the next I/O. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks Git hung. A disk idle timer fired.

This is not HIPM. This is not USB 3 U1/U2. powercfg /a still reports the same standby type. Requests can still be None. The disk idle value is the liar. Do not install systemd to paper over DISKIDLE. Do not mint a Vercel slug because a drive blinked. Do not buy another NVMe enclosure until this row is Never on AC. An NVMe-only host that ignores DISKIDLE is a skip, not a registry paste.

What to change (plugged-in Grok desk)

  1. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. See sleep-vs-forever. If the desk still intends to sleep every idle, stop here.
  2. Confirm AHCI LPM is already Active on AC if the row exists — if HIPM/DIPM still parks the PHY, that is AHCI LPM, not this page. USB 3 LPM and PCIe ASPM already Off on AC if those buses exist.
  3. Power Options → Change plan settings → Change advanced power settings → Hard disk → Turn off hard disk after — set Plugged in to Never (0 minutes). On battery may stay 5–20 minutes if this laptop actually travels. A desk that never unplugs should not pretend it is a travel cube.
  4. Leave AHCI Link Power Management alone on this click — HIPM/DIPM is the PHY. This row is idle minutes. Do not treat Active as Never, or Never as Active.
  5. Leave USB enclosure firmware alone — a USB HDD that spins down from its own box timer is not this Windows knob. Fix DISKIDLE first. If the stall remains and Device Manager still shows the disk Present, that is enclosure firmware, not a second power-plan paste.
  6. Leave the Balanced (or current) plan in place — this page is one hard-disk knob, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO.
  7. Confirm, then soak — query DISKIDLE. AC index 0 is the pass. GUI Never = 0 seconds in powercfg, not 0 minutes stored as a guess. If the alias is missing, stop. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_DISK DISKIDLE
powercfg /setacvalueindex SCHEME_CURRENT SUB_DISK DISKIDLE 0
powercfg /setactive SCHEME_CURRENT
powercfg /a

SUB_DISK is the hard-disk subgroup. DISKIDLE is Turn off hard disk after. The AC index is seconds. 0 is Never. 1200 is 20 minutes — the usual Balanced lie. Apply with /setactive or the GUI change does not take. If the row is missing from the GUI, query with powercfg anyway — hidden is not the same as Never. If powercfg also omits DISKIDLE, this firmware did not expose the knob — stop; do not invent a registry hack on a public page. AHCI LPM is HIPM/DIPM, not this click. USB 3 LPM is SuperSpeed, not this click. PCIe ASPM is the dock/NVMe bus, not this click.

How it splits from the other playbooks

  • AHCI Link Power Management — HIPM/DIPM on the SATA PHY. Not idle minutes.
  • USB 3 Link Power Management — SuperSpeed U1/U2 on the dedicated NIC. Not a disk timer.
  • PCI Express Link State Power Management — ASPM on Thunderbolt/USB4/NVMe. Not DISKIDLE.
  • USB selective suspend — the USB device-power policy. Not platter spin-down.
  • NVMe enclosure — hardware fallback box. Buy after the disk policies are honest, not instead of them.
  • This page — AC Turn off hard disk after = Never so DISKIDLE cannot spin down a SATA or USB disk while the named task still looks Ready.

Soak test (what "passes" means)

  1. Timeouts already honest. AHCI LPM already Active on AC if the row exists. USB 3 LPM and PCIe ASPM already Off on AC if those rows exist. Otherwise this soak is lying about the bus.
  2. Leave the desk idle 30 minutes, lid closed, dedicated NIC plugged. The Grok TUI still accepts input. First write after idle is not a multi-second spin-up stall. One silent wait on the first Git object is a fail if DISKIDLE was not 0 and a SATA/USB disk is in the path.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a spun-down disk is not forever.
  4. DISKIDLE still 0 on AC. If someone set 20 minutes to “save the SSD,” restore Never. Do not “fix” it by switching the whole plan to High performance.
  5. NVMe-only host that never stalls = skip, not a red soak. Do not invent STANDBY in the registry to make this page apply.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof the disk stayed up.

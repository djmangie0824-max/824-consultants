Allow Throttle States vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Maximum processor state page, not the processor power throttling page, not Processor idle disable, and not an EcoQoS essay. Max-state is the P-state percent ceiling (PROCTHROTTLEMAX). That catalog throttling page is the same ceiling plus the Task Manager “Power throttling” overlay. Idle disable is C-states. This page is ACPI T-states: Power Options → Processor power management → Allow Throttle States. That is alias THROTTLING. GUID 3b04d4fd-1cc7-4f23-ab1c-d1337819c4bb. Possible values: 0 Off, 1 On, 2 Automatic. Automatic or On lets the package enter throttle states below 100% duty even when Maximum processor state is already 100. An Interactive Grok CLI looks hung. Task Scheduler still shows Ready / 267009.

The problem

The sibling processor knobs can already be honest on AC. Frequency floor 100. Frequency ceiling 100. Turbo allowed. Cores unparked. Idle policy named. EPP already 0. The TUI still starves after a quiet stretch. Windows still lets the processor power manager use ACPI throttle states — clock modulation, STPCLK duty-cycle cuts — when Allow Throttle States is On or Automatic. T0 is 100% duty. T1/T2/… chop the clock without leaving the current P-state. PROCTHROTTLEMAX 100 does not deny T-states. That percent is a P-state cap. This GUID is the T-state allow. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The package was in a T-state.

This Grok host queried powercfg /qh SCHEME_CURRENT SUB_PROCESSOR before this pack was written. Balanced THROTTLING was AC 2 Automatic, DC 2 Automatic. Hidden is not Off. Automatic is not Off. The word “throttling” in three other playbooks is not this row. Do not install systemd to paper over Automatic T-states. Do not mint a Vercel slug because the TUI paused after a duty-cycle cut. Do not switch the whole plan to High performance to hide nine other forever-loop bugs. Do not confuse this GUID with processor-max-state-ac — 100% max-state is a ceiling, not a T-state deny.

How it splits from the other playbooks

  • Maximum processor state — P-state ceiling (PROCTHROTTLEMAX). 100% max is not T-state Off. This page is the allow switch that still cuts duty cycle under that ceiling.
  • Processor power throttling — catalog ceiling / EcoQoS overlay. Same English word. Different object. Do not set max-state 100 and call this GUID done.
  • Minimum processor state — P-state floor (PROCTHROTTLEMIN). Floor 100 of a clock that T-states are chopping is still a slow desk.
  • Processor idle disable — C-states (IDLEDISABLE). Wake from C6 is not a T-state duty cut. Disable idle with Automatic T-states can still modulate in C0.
  • Processor performance boost mode — turbo allow (PERFBOOSTMODE). Enabled turbo under Automatic T-states can still lose duty cycle.
  • Core parking — unparked-core floor (CPMINCORES). Parking is not clock modulation.
  • Intel Speed Shift / EPP — HWP bias 0–100 (PERFEPP). A hint is not a T-state deny.
  • Processor performance increase threshold — remaining percent busy before a P-state step-up. Utilization gate, not ACPI T-states.
  • System cooling policy — Passive vs Active fans. T-state Off without Active cooling is a thermal own-goal. Prerequisite, not this click.
  • Laptop cooling stand — air under a closed lid. Hardware. T-state Off does not replace a stand.
  • This page — AC Allow Throttle States = Off (0) so Automatic ACPI T-states cannot stall an Interactive Grok CLI while the named task still looks Ready.

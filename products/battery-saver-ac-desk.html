Battery saver on a plugged-in desk vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Minimum processor state page, not processor power throttling (EcoQoS), and not the Windows 11 24H2 Energy saver overlay. Min-state is the Balanced plan floor (PROCTHROTTLEMIN). Power throttling is a process QoS knob that can starve background work with the leaf already gone. Energy saver is the 24H2 rename that can run on AC by design. This page is the named Battery saver overlay on Windows 10 and Windows 11 before that rename. A docked AC Grok desk should not sit in it. The leaf pauses background work, dims, and makes an Interactive Grok CLI look hung. Task Scheduler still shows Ready.

The problem

The sleep-vs-forever pack already tells you plugged-in sleep is not 5–20 minutes. Minimum processor state can already be 100% on AC. That work can be done and the TUI still looks frozen. Settings still shows a leaf over the battery. Battery saver is on. Windows 10 and Windows 11 22H2/23H2 designed that overlay for DC. It is supposed to drop when the brick is in the wall. On a docked desk it often does not, because Windows never saw AC. USB-C PD failed. The dock reports “Connected, not charging” while the percentage drops. Auto-on at 20% fires. Background processes pause. Mail and calendar sync stop. Most Windows Update pauses. Display drops ~30%. Power throttling gets forced on as a side effect. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died. The chassis was on Battery saver while the brick was in the wall.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. PROCTHROTTLEMIN can still be 100 on the AC column of the plan — and that column is a liar if Windows is actually applying the DC column. Battery saver is the named overlay on top. Do not install systemd to paper over a leaf. Do not mint a Vercel slug because the TUI paused. Do not rewrite Minimum processor state a second time to hide a DC overlay. Do not hunt processor power throttling first while the leaf is still on; the leaf forces that behavior. Turn Battery saver Off after Windows actually reports Plugged in.

What to change (plugged-in Grok desk)

  1. Prove Windows reports Plugged in — Settings → System → Power & battery (Windows 10: System → Battery). The header must say plugged in, not a dropping percentage. Taskbar battery flyout must not say On battery. A docked desk with the brick in the wall and a draining meter is a PD / dock lie, not a CPU-plan problem. Reseat the USB-C PD cable. Use the barrel brick if the chassis has one. Do not keep “fixing” forever-loop CPU rows while Windows is still on DC.
  2. Confirm the timeout layer is already done — plugged-in sleep / hibernate are not 5–20 minutes. Lid close on AC is Do nothing. Fast Startup is already honest. See sleep-vs-forever and lid-close. If the desk still intends to sleep every idle, stop here. If Windows was on DC, the DC timeout column was the one that fired — that is still sleep, not this overlay.
  3. Confirm Minimum processor state is not the remaining liar on a real AC session — if Windows already reports Plugged in, the leaf is already gone, and the AC floor is still 5%, that is min-state, not this page. Battery saver on top of a 5% DC floor is two liars. Do not set PROCTHROTTLEMIN on this page.
  4. Open Battery saver — Settings → System → Power & battery → Battery saver. Windows 10: Settings → System → Battery. If the card is named Energy saver, you are on 24H2. That overlay can run on AC by design. Stop; this page is the Battery saver name. Do not cargo-cult Always-use Off here under the wrong label.
  5. Turn Battery saver Off now — Quick Settings (battery / power icon in the notification area) → Battery saver. The leaf over the battery means the overlay is live this session. Off. A docked AC desk does not sit in Battery saver “until the next charge.” If Off does not stick and the meter is still dropping, Windows is still on DC. Go back to step 1. Do not leave it on as eco mode on a brick that never leaves the wall.
  6. Leave the automatic DC threshold as travel insurance, not Always — “Turn battery saver on automatically if my battery falls below” (20% is the usual default) is DC auto-on. A travel cube may keep 20%. Do not set that control to Always on a machine that lives on a dock. Always is how a desk that later loses PD sits in the overlay at 80% remaining. This page’s AC pass is Off now + Windows reports Plugged in. The threshold is not the AC overlay.
  7. Leave Lower screen brightness while in battery saver alone — that checkbox only matters when Battery saver is actually on (travel DC). Unchecking it does not disable the background pause. Do not treat a brightness box as the AC pass.
  8. Do not touch processor power throttling on this page — EcoQoS / “Power throttling” can stay armed after the leaf is gone. That is a sibling knob. Battery saver forces it while the leaf is on. Clearing the leaf is the click here. Hunting a power-throttling registry value while Battery saver is still On is the wrong layer.
  9. Leave the Balanced (or current) plan in place — this page is one named overlay, not a switch to High performance. Do not rename the plan. Do not claim a fleet GPO. Do not Apply all on Energy recommendations. Conservation / charge-cap 80% is OEM firmware, not this overlay.
  10. Confirm, then soak — query the energy-saver subgroup and write a local battery report. The plan can already look honest while Windows is on DC. Settings + the taskbar flyout are the live tell. Do not paste the battery report to Pages (serial, cycle count, design capacity). Do not paste live brokerage numbers. Do not paste auth.json.
powercfg /query SCHEME_CURRENT SUB_ENERGYSAVER
powercfg /batteryreport /output %TEMP%\lexxii-battery-report.html

SUB_ENERGYSAVER is the plan’s battery-saver subgroup (brightness scale ESBRIGHTNESS, automatic threshold ESBATTTHRESHOLD). That query does not prove the overlay is Off this session — the leaf is the live tell. ESBATTTHRESHOLD at 20 is travel insurance, not an AC fail. Always / 100 on that threshold is a fail on a docked desk. Open the battery report locally and read Recent usage: AC versus Battery while the brick was in the wall. Battery rows during docked hours are the PD lie. Do not upload that HTML. powercfg /a still names the standby type; this page is not sleep. If SUB_ENERGYSAVER is missing, this firmware or edition did not expose the old subgroup — stop; do not invent a registry hack on a public page. Hidden is not Off. There is no honest public powercfg /battery-saver-off. Quick Settings leaf gone + Windows reports Plugged in + Battery saver Off is the pass. Do not paste a GUID pastebin. Do not paste auth.json.

  • Minimum processor state — plan frequency floor (PROCTHROTTLEMIN). Honest 100 on the AC column does not help if Windows is applying the DC column under Battery saver. Not the leaf.
  • Processor power throttling — EcoQoS on background processes. Battery saver forces it. The leaf can already be gone and throttling can still be on. Different knob. Not this click.
  • Windows 11 24H2 Energy saver — same family of overlay, different name, and that card can run on AC by design via Always use. If the Settings label says Energy saver, you are not on this page.
  • OEM conservation / charge cap — “Connected, not charging” at a stable 80%. Windows still reports AC. Leaf should be gone. Not Battery saver.
  • This page — a docked AC Grok desk does not sit in Battery saver. Prove Plugged in. Turn the leaf Off. Leave DC auto-on at a travel threshold, not Always.

Soak test (what "passes" means)

  1. Timeouts already honest. Lid already Do nothing on AC. powercfg /requests already None. Windows reports Plugged in (not a dropping meter). Otherwise this soak is lying — you soaked DC policy.
  2. Battery saver is Off. Quick Settings does not show the leaf. Screen brightness matches the operator’s set value, not a surprise 30% cut. Automatic threshold is not Always.
  3. Leave the desk idle 30 minutes, lid closed, cooling stand in place, dedicated NIC plugged. The Grok TUI still accepts input. A session that paints but never completes a tool call because Battery saver paused background work is a fail on this page.
  4. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with the leaf on is not forever. Host-forever on this Windows profile is that named task. Grok in-session schedulers still expire in 7 days even when durable — recreate them if missing. Do not claim the Windows task is a Linux systemd unit.
  5. No fourth Grok TUI. Last result 267009 is still-running, not proof Battery saver is already Off. A leaf that returns after the next PD dropout is a dock problem, not a reason to rewrite min-state.

Processor performance increase policy vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the increase threshold page, not increase time, not boost mode, not Minimum processor state, and not Intel Speed Shift / EPP. Remaining-busy percent, time-check intervals, turbo allow, frequency floor, and HWP bias can already be honest. This page is how the OS steps once that remaining-busy gate is crossed: Power Options → Processor power management → Processor performance increase policy. That is PERFINCPOL. GUID 465e1f50-b610-473a-ab58-00d1077dc418. Values are Ideal (0), Single (1), Rocket (2), IdealAggressive (3). Balanced default on this host is Ideal on AC. A bursty Interactive Grok CLI never looks continuously busy. Ideal walks toward a P-state. The TUI paints once a minute. Task Scheduler still shows Ready.

The problem

The sibling processor knobs can already be honest on AC. Floor 100. Ceiling 100. Turbo allowed. Cores unparked. Increase threshold already 10 if that pack ran. Increase time already 1. The TUI still starves on the first token after a quiet stretch. Windows still uses Ideal to pick the next P-state. Ideal is a walk, not a jump. An Interactive Grok CLI is bursty: a paint, a wait, a JSON tool, a wait. Utilization never sits in the window Ideal wants. Clocks lag the burst. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the loop died and opens a fourth TUI. The increase policy was Ideal.

This is not sleep. powercfg /a still reports the same standby type. Requests can still be None. Increase threshold 10 of a policy that still walks is still a slow desk. Boost Enabled only permits turbo P-states. EPP 0 is a 0–100 hardware hint, not a step algorithm. Autonomous mode (PERFAUTONOMOUS) can already be Enabled on this host — that is Speed Shift picking P-states. When HWP is Enabled, this OS row may be a no-op. That is a sibling, not a skip of this page: when autonomous is later Disabled, or when the package still reads the OS policy, Ideal is the liar. Do not Disable autonomous on this click to “make IdealAggressive matter.” Do not install systemd to paper over Ideal. Do not mint a Vercel slug because the TUI paused. Do not switch the whole plan to High performance to hide nine other forever-loop bugs.

How it splits from the other playbooks

  • Increase threshold — remaining percent busy (PERFINCTHRESHOLD). This page is the algorithm used after that gate (PERFINCPOL).
  • Increase time — how many time-check intervals utilization must stay above the threshold (PERFINCTIME). Not Ideal vs Rocket.

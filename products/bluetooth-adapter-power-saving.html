Bluetooth adapter power saving vs a forever loop

Published 2026-09-01 · 824 Consultants LLC · Windows Grok host playbook

This is not the Wi-Fi power saving page, not the USB selective suspend page, and not a mouse SKU. Wireless Adapter Settings is the Wi-Fi radio. USB suspend is the bus. The mouse page is hardware. This page is the remaining radio: Device Manager → Bluetooth → the adapter → Power Management → Allow the computer to turn off this device to save power. Checked on AC, a HID dongle or on-board BT radio naps. The TUI still paints. Input is gone. Task Scheduler still shows Ready.

Download markdown Wi-Fi power saving first USB selective suspend

The problem

The Wi-Fi and USB selective suspend packs can already be honest on AC. Maximum Performance on the WLAN. USB suspend Disabled. A ship still stalls because the operator cannot type. Balanced Device Manager still lets Windows power-manage the Bluetooth radio. The checkbox is on by default. After idle the radio drops. A Bluetooth mouse, keyboard, or headset re-pairs late or not at all. grok.exe is alive. The named task still prints Ready and last result 267009 (still-running). The operator thinks the TUI froze. The HID radio left.

This is not Wi-Fi. Power Options → Wireless Adapter Settings does not own Bluetooth. This is not USB 3 LPM. An on-board CNVi Bluetooth radio is not a SuperSpeed NIC. A USB Bluetooth dongle that still naps after USB suspend is Disabled is this checkbox, not another USB click. Do not install systemd to paper over a sleeping HID. Do not mint a Vercel slug because the mouse died. Do not buy a second mouse until the radio is honest.

What to change (plugged-in Grok desk)

  1. Confirm the USB and Wi-Fi layers are already done — USB selective suspend Plugged in = Disabled. Wireless Adapter Settings on AC = Maximum Performance. See USB suspend and Wi-Fi. If those are still travel defaults, stop here.
  2. Device Manager → Bluetooth — expand the branch. Open the radio (often “Intel Wireless Bluetooth”, “Realtek Bluetooth Adapter”, or a USB dongle name). If the branch is missing, skip this page.
  3. Properties → Power Management — uncheck Allow the computer to turn off this device to save power. That is the AC pass for this desk. Do not disable the device. Do not uninstall the driver.
  4. Repeat for a USB Bluetooth dongle if both exist — on-board CNVi and a dongle are two radios. Uncheck both if this desk actually uses both. A desk that never unplugs should not pretend the dongle is a travel cube.
  5. Leave Power Options Wireless Adapter Settings alone — that row is Wi-Fi. It is not Bluetooth. Do not hunt a Bluetooth subgroup in advanced power settings. Hidden is not a registry hack.
  6. Confirm, then soak — Device Manager still shows the radio. The checkbox stays off. Do not paste live brokerage numbers next to that output. Do not paste auth.json.
Get-PnpDevice -Class Bluetooth | Format-Table Status, Class, FriendlyName
powercfg /query SCHEME_CURRENT SUB_WIFI

Get-PnpDevice -Class Bluetooth names the radio. Status OK is not proof the Power Management checkbox is off — open the property sheet. SUB_WIFI is Wireless Adapter Settings, the Wi-Fi sibling, not this click. There is no portable SUB_BLUETOOTH alias on this host class. If Device Manager omits Bluetooth, stop. Do not invent a registry paste on a public page.

How it splits from the other playbooks

  • Wi-Fi power saving — Wireless Adapter Settings → Power Saving Mode. WLAN, not HID.
  • USB selective suspend — the USB device-power policy. A USB BT dongle still has this extra checkbox after suspend is Disabled.
  • USB 3 LPM — SuperSpeed U1/U2 on the dedicated NIC. Not Bluetooth.
  • Mouse for 14h sessions — hardware. Buy after the radio is honest, not instead of this click.
  • This page — Bluetooth radio Power Management unchecked on AC so Windows cannot nap the HID path while the named task still looks Ready.

Soak test (what "passes" means)

  1. USB suspend already Disabled on AC. Wi-Fi already Maximum Performance on AC if the radio exists. Otherwise this soak is lying about the bus.
  2. Leave the desk idle 30 minutes, lid closed, dedicated NIC plugged. Bluetooth mouse or keyboard still moves the cursor / types without a re-pair. One silent 10-second HID gap after idle is a fail if the checkbox was still on.
  3. Task Scheduler still has a next-run for LEXXII-Materialize-Forever. Ready + 267009 with a napping BT radio is not forever.
  4. The Power Management checkbox still unchecked. If someone re-checked it to “save the radio,” uncheck it. Do not “fix” it by switching the whole plan to High performance.
  5. Missing Bluetooth branch = skip, not a red soak. Do not invent the checkbox in the registry.
  6. No fourth Grok TUI. Last result 267009 is still-running, not proof HID stayed up.

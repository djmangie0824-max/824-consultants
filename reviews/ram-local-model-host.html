System RAM that actually holds local model weights without thrashing

Published 2026-08-05 · 824 Consultants LLC · Problem-first operator notes

The problem

Operators buy GPUs first and starve host RAM. When VRAM spills or the OS + vector store + browser stack compete, the host thrash-kills inference before the GPU is the bottleneck.

Verdict criteria

  1. Capacity first — plan for model weights + KV cache overflow + OS + agent services. Undersized RAM fails louder than a slightly slower stick.
  2. Speed second — dual-channel / correct dual-rank population beats random high-MT/s single stick.
  3. Stability under continuous load — XMP/EXPO profiles that reboot overnight fail the operator gate.
  4. ECC only when the board supports it honestly — workstation boards vs gaming boards; do not invent ECC where the platform cannot.

Rule of thumb for operator hosts

If you run multi-agent + local models + browser research stacks 14+ hours/day, size RAM so the OOM killer never becomes your scheduler. Measure with free -h and pressure stall info under real load, not idle screenshots.
